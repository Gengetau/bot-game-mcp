# 栖灯镇三维网页客户端：端到端演示与独立验收记录

日期：2026-11-12。验收人：没有参与客户端开发的「外人」，只按 `client/README.md` 的步骤从头走一遍。

## 环境

| 项 | 值 |
|---|---|
| 浏览器 | Chromium 153.0.8010.12，无头，Playwright，软件渲染（SwiftShader），容器 4 核 |
| Godot | 4.7.2.stable.official.ed1daf0bf（Web 导出，单线程，Compatibility 渲染） |
| Node | v22.23.4 |
| 引擎 | 子进程，`town.devLogin`，keys 认证（一个测试 AI 密钥），临时库，随机端口，`BOTGAME_TOWN_CLIENT_DIR` 指向导出目录 |
| 桌面上下文 | 1440x900，deviceScaleFactor 1，鼠标 |
| 手机上下文 | 390x844，deviceScaleFactor 2，`isMobile` + `hasTouch`，触摸 |

跑法：`npm run client:export`，然后 `npm run client:e2e`（约 3.5 分钟，不进 CI）。脚本是 `scripts/client-e2e.mjs`，
每次完整运行把结果写进 `client/demo/results.json`、把截图写进本目录。

桌面用 dsf 1 而不是 2 的原因：桌面 dsf 2 是 2880x1800（520 万像素），SwiftShader 只剩 1 到 2 帧每秒，
页面的时钟估计被拖慢（往返 1.5 秒），页面里的位置与服务器折线现算位置会差 0.7 到 1 米，那测的是渲染饥饿，不是客户端的位置逻辑
（实测：桌面 dsf 2 时步骤 8 的最大偏差 0.71 / 0.93 米，改 dsf 1 后 0.13 到 0.27 米）。手机（390x844，dsf 2，约 130 万像素）没有这个问题，用 dsf 2。

## 结果（最后一次完整运行：11 步全过；之后连续又完整跑了两遍，全部通过）

## 外人走 README 时发现并已处理的问题

1. **README 的启动命令走不通**：`BOTGAME_TOWN_CLIENT_DIR=client/town/build/web` 是相对路径，而 `npm run dev -w bot-game-mcp` 会先切到 `packages/engine`，
   目录就指到了不存在的地方，页面是 404「三维客户端还没有部署」。已改成 `"$PWD/client/town/build/web"` 并在 README 里写明原因。
2. **别人进镇、离开时页面不更新**（服务端只在有人走动时推场景快照，见「给服务端的发现」）：A 登录后 B 的页面一直看不到 A，直到 A 走动。
   客户端已加兜底：WebSocket 通着时每 3 秒再取一次 `GET /scene`。
3. **兜底带来的一个竞态（已修）**：晚到的旧 `GET /scene` 回应会盖掉 WebSocket 刚推来的新快照，把刚开始走的人「按回原地」冻结最多 3 秒。
   本脚本第一次完整跑就逮到了（步骤 2 / 8 偏差 7 到 8 米，线性增长）。已在 `_on_scene` 里丢弃 `serverTime` 比已应用的更老的快照。
4. **断线只有一个会闪的小点**：断线时界面没有文字，用户和截图都看不出来「重连中」。已在连接状态点旁加文字「重连中…」/「离线」（`#connText`）。

## 给服务端的发现（已修）

> 这一条随后已在服务端修掉：上线、离线、在场租约到期、改名、进出小游戏都会通知同一场景实例（`space.ts` 的 `touchScene`，带测试），客户端的 3 秒兜底也已去掉。下面保留当时的记录。

**场景快照的 WebSocket 推送不覆盖「有人进镇或离开」**。复现：开两个页面（或一个页面加一个 MCP AI 居民）进同一个场景，让其中一个进镇后站着不动，
另一个的页面里一直看不到它（`actors` 里没有），直到它第一次走动。原因：`packages/engine/src/world/service.ts` 的 `bumpSpace()` 只被 `space.ts` 里位置和导航变化的路径调用
（`space.ts` 约第 254、263、315、341、465、746 行），`enterWorld` 把居民置为在场（`present_since`）、离开、离线、被请出等不调用它，而 `sceneView`
又按 `present_since` 过滤在场的人。建议在在场状态变化（进入、离开、租约全部过期转离线、恢复在场）时对该居民所在的场景实例 `bumpSpace`。
修好后客户端的 3 秒兜底可以去掉（`main.gd` 的 `SAFETY_POLL_MS`）。

## 没能验证的事项

- **真机**：安卓 Chrome、iOS Safari（含 `connect-src` 同源 ws 在旧 Safari 的行为、音频手势、安全区）、Windows Chrome / Edge 都没有测。
- **Firefox、WebKit**：容器里没有。
- **声音**：客户端同事在无头 Chromium 里查过点进入后 AudioContext 为 running、被拦时静音可进，本脚本没有断言；没有听过音量和脚步声的效果。
- **帧率、功耗、内存、弱网**：软件渲染没有参考意义；没做弱网或丢包模拟。
- **高分屏的 3D 降分辨率**：只在无头环境见过（桌面 dsf 2 会触发），真机效果没测。
- **后台标签页**：浏览器暂停渲染循环后心跳和续租也暂停（在场租约 60 秒），回前台重新进入；本脚本没有覆盖。
- **登录票据兑换（非开发登录）流程**：脚本只用开发登录。
- **真实模型驱动的 AI 居民**：只用 `TownClient` 的 `navigate` 加手动续租，没有跑 `ResidentRunner`。

## 已知的小问题（不影响验收，没有改）

- 区域名标签（如「灯下广场」）会画到右上角「旧页面」按钮下面一点点（`05-desktop-unreachable.png` 右上角）。
- 只读横幅和提示条在窄屏 / 横幅出现时会重叠（`12-desktop-readonly-tab.png`）。
- 姓名牌贴着屏幕边缘时被截断（`12-desktop-readonly-tab.png` 右侧）。
- 位置精度断言的容差是 0.6 米：走路速度 2.4 米每秒，约 250 毫秒；无头渲染 5 到 8 帧每秒时，正常的采样误差就是几厘米到 0.3 米，超过 0.6 米说明页面没有拿到或没有应用服务器的折线。
