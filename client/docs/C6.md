## 2. 设计要点

- **NPC 并进角色表，类型靠字段不靠编号。** `main._on_scene` 把 `msg.npcs[]` 逐个复制一份、补 `kind="npc"`，交给同一套 `TActor`（插值、折线、动画都是居民那一套）。服务器的快照里 `npcs` 和 `actors` 仍然分开，所以出现在 `actors` 里的 NPC 一定是客户端自己补的字段；代码里没有任何一处靠 id 前缀 `npc:` 判断。`window.__town.actors` 仍然只有居民（旧步骤到处在数它）；NPC 在 `window.__town.npcs`（`id name x z nx ny moving pose role sitting outfit`）。
- **一次只开一张浮层卡。** 居民卡（`#peopleCard`）和 NPC 菜单（`#npcMenu`）都是挂在 `#dockOverlays` 上的小名牌纸，位置相同。`ctx.card_claim(fid)`：把卡的主人换成自己，并让上一个主人的 `on_card_yield()` 先收起；`card_release(fid)` 只在自己仍是主人时清掉。换人、离开（`hub.on_leave`）清空。
- **点选。** NPC 在 `actors` 里，`_nearest_pick`（E 键）和 `_on_tap`（点击）不用改，天然选得到；`_can_control(kind, pick_id)` 照常先问：共同活动中、在游戏桌上，点 NPC 或按 E 都被「走开」确认拦下（`hub.blocks_input` 非空），不开菜单、不发 `navigate`。`npc.on_pick` 排在 `people` 之前，只接管 `kind == "npc"` 的目标：近处直接开；连点两下（E E、双击）第二次直接返回 true，不重开；远处不接管（main 去走），记下「是在这里点的」，到了（`you_arrived`、`target.kind == "npc"`、编号对得上）才开。居民卡对 NPC 目标什么也不做。
- **远处点选的「是在这里点的」窗口。** 点的那一刻记下导航代号 `nav_gen`；main 的 `_do_navigate` 同步加一，所以看到 `pick_gen + 1` 就是「发出去了」；之后代号再变就是走的路上点了别处或停了，作废；一直没变成 `+1`（被拦下没发出）超过 2 秒，也作废。别处发起的走近（API 代发、另一台设备握着控制权）到达时不弹菜单。
- **请求。** 全部走 `ctx.act_once`（一次性、不动 pending、不睡眠重试、可复用请求号）。网络层失败（`net_fail`）时把服务器给回的请求号记在 `_pending[键]`，键带对象：问话是 `ask:<npc>:<topic>`，买是 `buy:<npc>:<shop>:<sku>:<qty>`，用户再点同一个对象才沿用，换话题、换商品、换数量、换 NPC 用新号；其余失败（服务器明确拒绝）清掉。同一个 NPC 上一次问 / 买还在路上，再点不发（在途键 `ask:<npc>` / `buy:<npc>`）。
- **两个代号。** `_sess`（会话：换人、离开加一）：在途响应回来对不上，整个丢掉（不写菜单、不记请求号、不出回执）。`_gen`（菜单：开、关、换 NPC 加一）：对不上的响应不再更新界面，但请求号的记账照做（网络失败仍记着，关菜单再开再问沿用同一个号），回执标 `stale`。
- **限流。** `error == "rate_limited"` 时 `reason` 是桶名，所以先看 `error`。冷却到期时刻 = 服务器时间 + `retry_after_ms`，对居民而不是对菜单，关菜单不清；网页按秒倒数，到点自己恢复按钮。限流前不预先灰掉按钮（不知道桶里还剩多少），服务器说了才灰。
- **买。** 不预先灰「买」（硬币不够由服务器说，菜单显示服务器的回执文字）；价格、库存来自 `/me` 的 `here.shops`；买成功后本地先减库存，再读一份新 `/me`（`_local_shop` 只盖到下一份 `/me` 为止）；`sold_out` 把本地库存归零，`closed` 把货架置灰。成交文字（「买了 N 件……」）只放在买家自己的菜单里：不进附近聊天、不进气泡、不进提示条；NPC 的那句泛泛的话照常作为 `chat` 事件给附近的人看（服务器就是这样设计的，里面没有买家名字和货物）。
- **菜单自动收起。** 场景换了、NPC 不在快照里了、进了小游戏、走远（超过「够得着」+ 1.5 米）；点了「走过去」正在走时不因距离收起。
- **外观。** 用现有的 CC0 居民模型（掌柜：盗贼身体、米白上衣；闲逛者：骑士身体、薰衣草上衣）；`npc_look.gd` 在骨架空间里生成围裙 + 小木牌（挂在胸骨上）、软帽（挂在头骨上，跟着头动）、读书时的书（挂在胸骨上，只在 `pose == "read"` 且没在走时显示）。`read` 姿态是站着加一本书（统筹决定 8）。
- **名牌。** 居民牌是深色药丸，NPC 牌是奶油色小木牌（样式在 `npc.css`），尾巴上带「店」或「闲」（文字来自 `npc.html` 的文字库，经 CSS 变量交给 `::after`，JS 里没有汉字）。`hud.js` 的 `setTags` 给居民牌 z-index 5 / 4，其余 3，所以 NPC 的牌天然在居民牌下面；`npc.gd.tags()` 再按 CSS 像素算一遍重叠，和任何居民牌重叠超过较小那块的一半就不画。

## 3. 「遍历 actors 的地方」逐处核查

NPC 现在在 `main.actors` 里，每一处按「居民」处理 `actors` 的代码都要想一遍 NPC 该不该算。

| 位置 | 怎么处理 |
|---|---|
| `main._on_scene` 末尾清理（`for id in actors.keys()`） | 用 `seen` 记快照里出现过的 id，NPC 也加进去；快照里不再有的 NPC 消失（走出场景 / 进了私宅快照没有 `npcs`） |
| `main._clear_actors` | 全清，NPC 一起 |
| `main._on_tap`（点选盒） | NPC 的盒半宽 0.35（居民 0.5），按模型轮廓收紧；旧步骤用的 `clearSpot` 把 NPC 也算进挡路的人 |
| `main._nearest_pick`（E 键） | 不改：NPC 在 `actors` 里自然被选到，结果走同一个 `_can_control` 和 `features.on_pick` |
| `main._do_interact` | 不改。`features.on_pick` 没接管（比如远处）才走到「靠近 ta」 |
| 帧循环里每人 `tick` / `_update_sitting` | `_update_sitting` 对 NPC：`set_sitting(pose == "sit" and not moving)` 后直接返回，不查茶桌座位表 |
| 遮挡淡出用的 `heads`（`update_view`） | 保留：NPC 的头也会被建筑挡住，也该让楼淡出 |
| `main._update_tags`（名牌） | 跳过 `kind == "npc"`；NPC 的牌由 `npc.gd.tags()` 加 |
| `main._push_debug` | `actors` 只放居民；NPC 放 `npcs` |
| `activity.gd` 选座 `others` | 保留：长椅 / 座位上有 NPC 就是被占了，选座要避开 |
| `activity.gd` 调试里坐着的人 | 过滤 NPC |
| `game.gd` 选座 `others` | 保留，同上 |
| `people.gd` tick 里「认识一下」候选、`_pickable` | 只收 `human` / `agent`，NPC 本来就不入选；`you_arrived` 里 `target.kind != "actor"` 的不处理（单测） |
| `nearby.gd` 「附近没人」 | 不数 NPC（NPC 不是听众） |
| `bubbles.gd` `tag_obs`（气泡避让名牌） | 保留：NPC 的牌也是障碍。宽度按居民牌估，NPC 牌多一个小标记，会略窄；已知小缺口 |

## 4. 输入先后（单测里逐条喂过）

`client/tests/npc_feature_test.gd` 用假的 `ctx` 直接喂 `on_me`、`on_event`、`on_pick`、`on_ui`、`tick`：

1. 近处点：直接开；再点一次（连按两下 E）返回 true 且只开一次；点自己 / 点物件不接管。
2. 远处点 → main 发出 navigate（导航代号 +1）→ 到达事件 → 位置跟上 → 开。
3. 到达事件的先后：没在这里点过就到达（别处发起）不开；点了闲逛者、到的是掌柜不开；到达的目标是居民不开。
4. 问话在路上时再点：不再发；未知话题不发。
5. 回执迟到：离开（`on_leave`）后迟到的回执整个丢掉，不留回执记号；关掌柜菜单、开闲逛者菜单之后迟到的回话不写进新菜单，回执标 `stale`；菜单关掉后迟到的网络失败，请求号仍记着，再开再问沿用。
6. 网络层失败：同一话题沿用同一请求号；换话题、换数量、换商品用新的；成功之后记号清掉。
7. 限流：冷却内不发；冷却过了可发；关了再开仍在冷却。
8. `not_here` 关菜单并提示一句；`sold_out` 本地库存归零；`closed` 置灰且不再发；`insufficient_coins` 不关菜单、不弹 toast。
9. `too_far`：显示「走过去」；点「走过去」调 `c6_approach`；位置到了不再显示「正在走」。
10. 迟到的旧 `/me`：买成功后本地库存先减，新 `/me` 到了用它的数；`/me` 的库存直接用。
11. 自动收起：场景换了、进了小游戏、走远、NPC 不在了。
12. 卡的互斥：居民卡 claim 后菜单收起；开菜单后主人是 npc；关菜单释放。
13. `people.gd`：对 NPC 目标 `on_pick` 返回 false；NPC 目标的 `you_arrived` 不开居民卡。

已知的迟到风险：买成功后到下一份 `/me` 到达之前，若有一份「买之前发出」的旧 `/me` 恰好晚到，货架库存会短暂显示成旧数（`context.version` 不是逐动作的戳，没法靠它判新旧）。处理办法是买成功后总再读一份新 `/me`，晚到的旧 `/me` 之后总有一份新的盖上，最多错一两秒；价格不受影响，服务器是最终裁判。

## 5. 对 9 个「待统筹决定」的回答

1. NPC 并进 `main.actors`，字段 `kind="npc"` 由客户端补；上面第 3 节是逐处核查表；`__town.actors` 只有居民，`__town.npcs` 单放。
2. 浮层卡互斥用 `card_claim` / `card_release` / `on_card_yield`，居民卡和 NPC 菜单都用；e2e 步骤 84 测来回开。
3. `you_arrived` 的 `target.kind == "npc"` 只由 `npc.gd` 处理，且只处理在本页点出来的那个编号；`people.gd` 忽略非居民目标。
4. 附近聊天里 `kind_of` 认 `npc`，模板多一个「NPC」标记，只在 NPC 发的那一行显示。
5. `TOWN_PARAMS` 加了 `npcStayMinMs: 20000`、`npcStayMaxMs: 40000`。
6. `clearSpot` 把 `scene.npcs` 算进去；NPC 的点选盒收紧到 0.35 半宽。
7. 外观：现有 CC0 模型 + 两套新配色 + 程序生成配件，没有新的第三方素材；名牌上的「店」「闲」来自文字库，牌和居民牌一眼分得出来。
8. `read` 姿态是站着加一本书。
9. 不预先灰「买」，显示服务器回执文字，价格和库存来自 `here.shops`。

## 6. 已知缺口与要真机看的

- 配件的真实观感要在手机真机上看（iOS Safari、安卓 Chrome、微信 X5）：软帽的大小、围裙在小屏上是否糊成一片、`read` 姿态的书。
- 服务端缺口（要统筹决定，客户端没动 `packages/`）：`ask_npc` 的回执没有统一给出「这次问话让 NPC 说了什么」之外的结构化字段（够用）；`/me` 没有逐动作的版本戳（上面第 4 节最后一段）；NPC 换位置时不发事件，菜单开着时靠每帧位置判断离开。
- 迷你游戏里的 NPC 收起：进了小游戏就收菜单；没有为「游戏桌旁点 NPC」单独做 e2e（用共同活动的拦截做了，路径同一个 `blocks_input`）。

## 8. D1：E 键选物件，按「离它最近的使用站位」算远近

**问题。** 原来 `_nearest_pick` 拿「我到物件中心」和「我到别人（含 NPC）」比。书架中心在 (28, 2.5)，使用站位在 (26.25, 3.75)、(28.25, 3.75)、(30.25, 3.75)，闲逛者读书的落脚点是 (32.25, 3.75)。人站在最东边的站位上按 E：到书架中心 2.57 米、到闲逛者 2 米，弹出来的是闲逛者的菜单。站在物件的使用位置上却用不了这个物件，是错的。

**规则。** 物件的距离 = min（到物件中心，到它每一个使用站位）。人和 NPC 的距离不变（到显示位置）。范围仍是 `INTERACT_RANGE`，严格小于才替换，先比物件后比人，所以等距时物件赢。这样只会让物件「更近」，原来选得中的物件不会变得选不中。点击（`_on_tap`，走射线）不经过这里，没动。

**实现。** `client/town/scripts/pick_logic.gd`（`nearest` / `object_distance`，纯函数，不碰节点）；`main.gd` 的 `_nearest_pick` 只准备输入（`world.scene_objects(cur_scene)` 每项的 `center`、`anchors`，加上 `actors` 里除自己外的显示位置），两个调用点（`_do_interact` 里等待前后各一次）不用动。

**单测。** `client/tests/pick_logic_test.gd`（22 项）：站在书架站位 (30.25, 3.75)、闲逛者 (32.25, 3.75) 选书架；同样位置但物件没有站位则选人；离 NPC 0.9 米、离站位 1.1 米选 NPC；无站位按中心；范围内什么都没有、正好等于范围都是 none；中心在范围外而站位在范围内选得中；物件和人等距物件赢；多个物件取最近。

**浏览器步骤。** `80-npc.mjs` 的 84.1：A `navigate` 到站位 (30.25, 3.75)；等闲逛者走到 (32.25, 3.75) 并停下（现读 `scene.npcs`，不在走、离落脚点不到 0.3 米；每站停 20 到 40 秒，最多等 240 秒）；先断言前提（到闲逛者 2 米、到书架中心 2.57 米），一律不接管（`pickStub('-')`）下按 E，读 `_pick` 记录，按完闲逛者仍然停着才算数（否则重来，最多四轮）；断言记录是 `(obj, bookshop:shelf)`。收尾 `leave_interaction`、撤假接管。

**反向验证。** 见第 10 节。

## 9. D2：只在调试模式下生效的「隐藏 NPC」开关

**为什么。** 闲逛者每隔几十秒在广场两张长椅和书架之间走，正好穿过居民出生点一带。旧步骤（1 到 15、20、25、30、40、50、60）写的时候镇上没有 NPC：E 键选最近的、点地面、截图、桌牌让位都可能被路过的 NPC 搅乱（25.2 撞上过一次、40.1 撞上过一次）。逐步去修是打地鼠，所以让旧页面回到 C6 之前的样子。

**开关。** 页面全局量 `window.__townHideNpcs === true`，**只在 `?debug=1` 时才认**（和 `window.__town` 同一个条件）：
- 启动时 `main._ready` 经 `bridge.hide_npcs_flag()` → `TownHud.debugHideNpcs()` 读（该函数在 JS 里也先看 `DEBUG`），再由纯函数 `debug_flags.gd` 的 `hide_npcs(debug, flag)` 定夺。页面全局量不受刷新之外的事情影响，所以刷新、重新登录都撑得住。
- 运行时：`window.__town.hideNpcs(true|false)`（`hud.js` 的 `debugSet` 里，和 `pickStub` 并列；它同时把全局量写回，再 `emit('debug_hide_npcs')`，Godot 一侧 `_set_hide_npcs` 同样过 `debug_flags.gd`）。切换后用「最近一份被采用的快照」（`_last_scene`）重放一遍 `_on_scene`（`serverTime` 相等不算旧快照），立刻生效，不等下一份。
- 生效的样子：`_on_scene` 里 `npcs` 当成空数组。已有的 NPC 角色走「快照里没有了」的同一条清理路径：角色、名牌、点选盒没了，菜单由 `npc.gd` 的 tick 发现「NPC 不在了」收起；`__town.npcs` 是空的。服务器一点没动：NPC 仍在、仍占出生点、`ask_npc` 仍可用。
- 对冻结文件的改动：`hud.js`（加了 `d.hideNpcs` 和 `TownHud.debugHideNpcs`，共 8 行；运行时入口必须在 `__town` 上，而 `debugSet` 每 100 毫秒整体替换 `window.__town`，只能写在 `hud.js` 里，和 `pickStub` 同一个办法）；`bridge.gd`、`main.gd` 的改动仅限这条开关与 D1。

**谁默认隐藏、谁显示。**
- `scripts/client-e2e.mjs` 的 `newPlayer(browser, label, ctxOpts, { wsGate, npcs = false })`：`addInitScript` 里默认设 `window.__townHideNpcs = true`；`{ npcs: true }` 不设。`pair({ npcs })` 把选项传给两个页面。11 号步骤里不经过工厂的 `page2` 自己设了。
- `80-npc.mjs` 的 A、B（`h.pair({ npcs: true })`）和傍晚页面 C 都显示 NPC；84.2 里临时开的 D（默认）隐藏，E（不带 `?debug=1`）无视开关。
- `clearSpot` 只在页面显示 NPC（`p.npcs`）时才把 `scene.npcs` 算作挡路的。
- 40 号文件：D2 之后页面看不到 NPC，原来的站位 (15.5, 11.2) 够用，前一轮挪到 (17.5, 3.5) 的改动已改回（`git diff claude/loving-ride-s01h0g -- scripts/e2e/steps/40-activity.mjs` 为空）。

**单测。** `pick_logic_test.gd` 里 4 项：调试开 / 全局量设了 → 隐藏；调试开 / 没设 → 显示；调试关 / 设了 → 显示（无视）；两个都没有 → 显示。

**浏览器步骤。** `80-npc.mjs` 的 84.2：显示 NPC 的页面 A 里 `__town.npcs` 有两个、服务器有两个；默认页面 D 登录，屏障是 D 的快照里已经看得到 A（居民和 NPC 在同一份快照里）、此刻 A 的页面还在显示两个 NPC，再多等几份快照，然后断言 D 的 `__town.npcs` 为空、`#tags .tag.npc` 为零、服务器仍有两个 NPC；A 站在掌柜旁开着菜单，`__town.hideNpcs(true)`：NPC 没了、菜单关了、名牌没了、全局量写回；`hideNpcs(false)`：NPC 回来、菜单不自己重开；最后一个不带 `?debug=1` 的页面 E（全局量设了、没有 `__town`）仍然看得到 NPC 的名牌。

**反向验证。** 见第 10 节。
