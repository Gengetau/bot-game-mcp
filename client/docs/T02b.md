# T02b：公共厨房的标准工位样件（灶台）

按 `client/docs/T02a.md` 冻结的契约做的第一件「真」资产：公共厨房里的砖砌双眼灶台 `kitchen/stove_station`。
它同时是一次试验：Antigravity（agy）拿着任务包、只用 Blender 脚本从零建模，出来的东西在实际镜头下站不站得住。
**结论要主人看图来下**：过关就照这个路子做首区的资产套件（T05），不过关就退回用 CC0 素材包改色拼装（`docs/art/standard.md`）。

## 交了什么

| 文件 | 内容 |
|---|---|
| `client/art_source/kits/kitchen/stove_station/build.py` | 源（agy 写的，419 行，只用 `kit_lib` 的函数，没有外部素材） |
| `client/town/assets/kits/kitchen/stove_station/` | `stove_station.glb`（159,076 字节）、`.glb.import`、`.tscn`、`manifest.json`（都是 `build_kits.sh` 生成的） |
| `client/docs/T02/shots/kitchen/` | 实际镜头的对照条 `strip-day.png`、`strip-night.png` 和 `results.json` |

统计（清单里的数）：1588 个三角形、21 个网格；包围盒 2.0 x 1.907 x 1.51 米，占地 2.0 x 1.5 米；四个状态 `idle` / `busy` / `done` / `fault`；
`state_busy` 一段循环动画；锚点 `anchor_use_1`（-0.25, 0, 1.5）、`anchor_use_2`（0.75, 0, 1.5）和地图里 `kitchen:stove1` 的两个使用位对得上，
另有 `anchor_put_1`（台面）、`anchor_fx_1`（锅口上方）。

四个状态怎么分：

- `idle`：灶口是暗的，两口锅盖着盖。
- `busy`：灶口里是发光的橙色火，锅盖掀开，锅口上有浮动的蒸汽（循环动画）。
- `done`：火灭了只剩暗红的余烬，台面上多出盛好的碗和盘。
- `fault`：锅歪了，台面和灶口上方是深灰黑色的烟团，没有橙色的火。

## 怎么看

```bash
npm run client:export
npm run client:shots -- --kit=kitchen      # 真实 Chrome：默认视角、最近缩放、夜里，四个状态各一张，拼成对照条
```

或者自己开页面：`/town/3d/?debug=1&props=kitchen`，走进公共厨房，控制台里 `__town.setPropState('kitchen:stove1', 'busy')`（传空串解除）。
不带 `?debug=1` 的页面看不到它：**默认的外观表没有指向这件资产**，灶台还是原来程序生成的样子。

## 验证记录

- `bash client/art_source/build_kits.sh kitchen/stove_station`：Blender 导出、Godot 导入、生成包装场景和清单、校验 77 项 0 失败（agy 的脚本第一次构建就过了，没有返工）。
- `npm run client:assets:check`：3 件资产 0 失败。
- 真实 Chrome（AMD Radeon 780M，1440x900，渲染比例 1.0，画质高）下 `--kit=kitchen`：12 张全部截成功，四个状态都切得过去，页面没有报错；帧率 60 上下（那一刻显卡没被别的程序占着，见 `client/docs/T01.md`）。
- 统筹看图的判断（不是结论）：默认视角下它在画面里大约 100 像素宽，轮廓认得出是灶台，四个状态靠颜色分得清（橙色的火、白色的汽、黑色的烟）；
  最近缩放下砖缝、锅、碗的细节成立；夜里使用中的火和完成后的余烬会发光。和镇上程序生成的房子、Kenney 的道具放在一起不跳。

## 和任务包的出入

- 三角形 1588，任务包写的上限是 1500（多 88）。那个上限是统筹拍的数，不是预算（预算要等样板在最低设备上跑过才冻结，见 `docs/art/standard.md`），没有让它返工。
- 所有状态加起来的包围盒在 +z 方向超出占地 1 厘米（`state_*` 的部件，不是常显部分）。
- agy 的无头模式不能自己跑命令（这个账号没有 auto 模式，需要权限的命令被自动拒绝），所以它只写了 `build.py`；
  构建、校验、台账登记、截图都是统筹做的，它也就没有交汇报。以后派给它的任务要么不依赖跑命令，要么由统筹替它跑完把输出贴回去。

## 没做的

- 没有进默认的外观表，也没有替换线上的灶台：等主人定。
- `done`、`fault` 现在没有服务端数据来源（T04 的事），只能用调试钩子切出来看。
- 没有在手机和别的显卡上看过。
- 灶口朝向：地图里的物件还没有 `facing` 字段，现在按 0 摆（正面朝南，对着使用位），和两个灶台的使用位方向一致。
