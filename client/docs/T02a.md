# T02a：物件节点与资产管线

打通「Blender 脚本 -> GLB -> Godot 包装场景 -> 游戏里带状态的可交互物件」这条链，并写定资产契约（能被机器校验）。
用两件占位样件证明它能重建、重导入、在游戏里按状态切外观；同时接通建筑的替换入口。美术标准整体见 `docs/art/standard.md`，这里只写这条链的契约和做法。

## 一眼看懂

```
client/art_source/kits/<套件>/<资产编号>/build.py     源：Blender 无头脚本，从零生成模型并导出 GLB
        │  bash client/art_source/build_kits.sh        （npm run client:assets:build）
        ▼
client/town/assets/kits/<套件>/<资产编号>/
    <资产编号>.glb          运行资源（导出物，进仓库）
    <资产编号>.glb.import   Godot 导入记录（进仓库；里面有 GLB 的 uid，删了重导会换 uid）
    <资产编号>.tscn         包装场景（脚本生成，不手改）：根挂 scripts/stateful_prop.gd，子节点是导入的 GLB
    manifest.json           清单（脚本从 GLB 算出来，不手填）
        │  外观表条目 {"scene": "...tscn"}
        ▼
world.gd 按物件实例化 -> 按服务端数据切状态
```

命令（Windows 的 Git Bash 和 Linux 都行；`BLENDER` 要 Blender 4.2 以上，实测 5.2.3 LTS；`GODOT` 要 4.7.x，路径带空格也行）：

```bash
export BLENDER="D:/steam/steamapps/common/Blender/blender.exe"
export GODOT="D:/steam/steamapps/common/Godot Engine/godot.windows.opt.tools.64.exe"
npm run client:assets:build                              # 全部资产：build.py -> 导入 -> 包装场景和清单 -> 校验
bash client/art_source/build_kits.sh sample/station_sample   # 只建一件（<套件>/<资产编号>，可写多个）
npm run client:assets:check                              # 只校验（不需要 Blender）；任何一条不过就非零退出，输出哪件资产的哪一条
```

## 谁说了算

- **位置、占地、使用位**：服务端地图（`town-map.ts`）说了算。资产不决定碰撞和可走范围；门洞、墙的碰撞对建筑同样只看地图。
- **朝向**：这一段不改服务端。客户端「有朝向就用」：地图里的物件带 `facing`（弧度）就把包装场景绕 y 转这么多，没有就是 0。`facing` 的正负号和 0 朝哪边，等服务端真的加了这个字段（首区灰盒）时对一遍。
- **资产自己声明的锚点**：`use`（玩家站位，只是「这件资产希望人站在哪」，用来和地图的使用位对账，不决定谁站哪）、`put`（物品放置点）、`fx`（特效位置）。`put` 和 `fx` 纯属表现，只在客户端用。
- **状态**：资产只声明它有哪些外观状态；什么时候进哪个状态由服务端的数据决定，客户端只做「服务端数据 -> 状态名」的映射（`prop_state.gd`）。资产上的脚本不许结算、改库存或发请求。
- 首批状态名固定四个：`idle`（空闲）、`busy`（使用中）、`done`（完成）、`fault`（异常）。

### 服务端现在能给什么（`here.objects[]` 的核对结果）

`/me` 的 `here.objects[]`（`views.ts:126` 的 `objectsIn` 加 `near`）每一项是：

| 字段 | 内容 |
|---|---|
| `id` | 物件编号，如 `kitchen:stove1` |
| `type` | 物件类型，如 `stove`（不是 `kind`；`kind` 是 `/map` 清单里的叫法） |
| `label` | 给人看的名字 |
| `action` | 这件东西能做的活动 `{def, name, cost, min, max}`，没有就是 `null` |
| `active` | 正在占着它的共同活动（`InteractionView`），没有就是 `null`；里面有 `status`（只会是 `open` 报名中或 `running` 进行中，查询就只选这两种）、`participants`、`startedAt`、`endsAt` 等 |
| `near` | 我够不够得着 |

没有顶层的 `status` 字段，没有「完成」「故障」的数据。所以：`active == null` 是 idle，`active` 是对象（open 或 running）都是 busy（服务端对这两种都拒绝别人新开，见 `interact.ts` 的 busy）。`done` 和 `fault` 现在没有数据来源，靠调试钩子切出来看。`here.objects` 只含我所在空间的物件；不在列表里的按 idle。映射在 `client/town/scripts/prop_state.gd`，有单测。

## 资产契约

### 节点命名（Blender 里就这样命名，GLB 里不变，包装时据此识别）

| 名字 | 含义 |
|---|---|
| `base*` | 任何状态都显示的部分（`base`、`base_top`、`base2` 都行，`baseball` 不行） |
| `state_<状态名>*` | 只在该状态显示。状态名是 `state_` 后面到下一个下划线的小写字母数字（`state_busy_flame_1` 属于 busy） |
| `anchor_use_<n>`、`anchor_put_<n>`、`anchor_fx_<n>` | 空节点锚点，局部坐标；朝向用节点自己的旋转（`use` 锚点的 +z 是「人脸朝的方向」） |
| `fade*`（可选） | 挡镜头时要淡出的部分（建筑的屋顶、上半墙）。平时常显；一件资产的所有 `fade*` 一起淡出 |
| 动画 `state_<状态名>` | 进入该状态时播放；名字后面加 `-loop`（`state_busy-loop`）表示循环，Godot 导入时去掉后缀并设成循环 |

规则（`kit_lib.py` 导出前会查，`check_assets.gd` 校验时也会查）：

- 名字只许小写字母、数字、下划线，以字母开头，全资产唯一；根空节点名等于资产编号。
- 名字不能以 `_col _colonly _noimp _loop _cycle _occ _rigid _navmesh` 等 Godot 导入指令词结尾（Godot 会据此改节点），动画名除外（`-loop` 是想要的）。校验还会核对「GLB 里写的名字」和「导入后的名字」一致。
- 每个网格自己或某个祖先要叫 `base*` / `state_*` / `fade*`；子节点（分组下的网格）可以随便起合法的名字，显示与否跟着祖先走。
- 至少有 `base*` 和 `state_idle*`（idle 没有几何就建一个空节点叫 `state_idle`）。
- 物件缩放必须是 1（缩放烘进顶点）；不支持灯、相机、骨骼蒙皮（居民不走这条链）。

### 颜色约定

- 材质不在 GLB 里（导出时 `export_materials=NONE`）。进游戏后 `world.gd` 把所有网格换成城镇着色器（`assets/shaders/town.gdshader`）的材质：**颜色 = 色板贴图 x 顶点色**，昼夜和发光就和街景一致。
- 顶点色（`COLOR_0`，Blender 里是名为 `Color` 的 FLOAT_COLOR / CORNER 颜色属性）放全部颜色，是**线性值**，和 `mesh_builder.gd`（`TMB`）里的 `Color(r, g, b)` 直接对应（实测 Blender 写的值导入后原样不变，没有 sRGB 转换）。
- 顶点色的 **alpha 是发光遮罩**：1 = 不发光，越小越亮（夜里发暖光）；`kit_lib.mesh(..., glow=0.9)` 写成 alpha 0.1。
- 所有顶点的 UV 都指向色板贴图左上角的纯白块：glTF 的 UV 是 `(0.015, 0.015)`（`mesh_builder.gd` 的 `WHITE_UV`；Blender 的 V 轴向上，所以在 Blender 里写 `(0.015, 0.985)`，`kit_lib` 会处理）。这样色板贴图乘上去还是白色，颜色全来自顶点色。
- 面用平面着色（每个面独立法线），和程序生成的几何一致。

### 单位和坐标

照 `client/art_source/README.md`：米；Y 向上；原点在底面中心；缩放烘进顶点。`kit_lib.py` 里的函数一律用「游戏坐标」（x 右、y 上、z 朝前，也就是 Godot 的），Blender 的 Z 向上只在 `g2b()` 里转一次，不许每件资产手工补偿。校验要求 `base*` 的最低点在 y=0、占地中心在 x=z=0（容差 2 厘米）。

**原点的约定**：功能物件的原点在占地中心（`footprint` 的中心）的地面上，正面朝 +z；世界按服务端给的占地中心摆。**建筑**的原点在「外框」中心的地面上：普通房子的外框是室内矩形四周各加 0.65 米，会馆的外框是 `Rect2(front_x - depth, z0, depth, z1 - z0)`（都是 `town_art.gd` 的 `build_house` / `build_hall` 返回的 `outer`）。

### 清单 `manifest.json`

由 `kit_wrap.gd` 从 GLB 算出来写，不手填；键排序、两空格缩进、数字取到 1e-4、末尾一个换行，同样的 GLB 重跑逐字节相同。

| 字段 | 内容 |
|---|---|
| `id`、`version`、`kit` | 资产编号、版本（build.py 里 `begin(...)` 的参数，改了模型就加 1）、套件 |
| `source` | `script`（build.py 相对仓库根的路径）、`blender`（导出时的 Blender 版本） |
| `size` | 全部网格（含所有状态、淡出部分）的包围盒尺寸，米 |
| `bounds` | 同一个包围盒的 `min` / `max` |
| `footprint` | 常显部分（`base*` 和 `fade*`）在 x、z 上的宽深，米 |
| `states` | 状态名数组（按字典序） |
| `anchors` | 每个 `{name, kind, pos, yaw}`；`pos` 是资产局部坐标（米），`yaw` 是绕 y 的度数，范围 (-180, 180] |
| `animations` | 每个 `{name, state, loop}` |
| `stats` | `triangles`、`material_slots`（每个网格一个槽；进游戏后都被换成城镇着色器）、`meshes`、`textures`（路径数组，目前恒空） |
| `origin` | 来源和许可（自制写「自制」） |

## 校验（`client/tools/check_assets.gd`）

对 `assets/kits/` 下每件资产：清单齐全且能解析、id / kit 和目录一致；包装场景能加载、根挂着 `stateful_prop.gd`、**就是生成脚本的输出**（没被手改）；清单里的状态、锚点、动画在场景里都找得到，**反过来场景里多出来的也算不一致**（清单过期）；有 `base*` 和 `state_idle*`；尺寸、占地、统计、版本和清单一致，清单文本等于从 GLB 重新算出来的；每个网格都有顶点色和色板纯白块的 UV；导入后的节点名和 GLB 里的一致；每个网格有归属。

## 客户端运行时

- `scripts/kit_logic.gd`（`TKitLogic`）：命名约定的纯函数（节点名 -> 角色、给定状态谁显示、状态名解析），`client/tests/kit_logic_test.gd` 单测。
- `scripts/stateful_prop.gd`（`TStatefulProp`）：包装场景的根。`set_state(名)`（显示 `base*` / `fade*` 和 `state_<名>*`，隐藏其它 `state_*`；有同名动画就播；不认识的状态名退回 `idle` 并记一条警告）、`get_state()`、`states()`、`anchor(名)`（全局变换；不在场景树里也能算）、`anchors(类别)`、`local_bounds()`、`fade_bounds()`、`apply_materials()`。只做表现，不结算、不发请求。
- `scripts/prop_state.gd`（`TPropState`）：服务端数据 -> 状态名。
- `art.gd`：外观表条目支持 `scene`。有 `scene`（且文件存在）的种类不再走 `parts()` 拍平网格，`proc_name()` 也返回空；`scene` 文件不存在就当没有这个条目（回到 `model` / `proc`）。`art_private/art_table.json` 里同名条目照样覆盖。键：功能物件用 `prop.<物件种类>`（灶台是 `prop.stove`），建筑用 `building.<区域编号>`（公共厨房是 `building.kitchen`）。
- `world.gd`：
  - `_build_interactables()`：种类的外观表条目有 `scene` 时实例化包装场景挂到场景根下（不进 MultiMesh），按物件编号存引用；点选盒高度取包装场景的包围盒，标牌高度取常显部分的高度，不再查 `INTERACTABLE_MODEL_H`。没有 `scene` 的种类行为和以前完全一样（`client/tests/kit_feature_test.gd` 里有「没有 scene 时点选盒还是 3.05」的断言）。程序灶台在灶口前的那个暖光晕（`glow`）在 scene 版本里不画：发光由资产自己的顶点色 alpha 负责。
  - 接口：`set_object_state(场景, 物件, 状态)`、`object_state(...)`（找不到是空串）、`object_anchor(...)`（找不到是 `null`）、`sync_object_states(场景, here.objects)`、`force_object_state(物件, 状态)`、`props_info(场景)`；找不到物件或不是带状态的节点时安静地返回。
  - 材质：实例化后所有网格换成 `_mat_static`（城镇着色器，全镇共用，昼夜 `town_night` 是全局量）；`fade*` 下的网格用复制出来的一份，登记进 `_fade_items`，一件资产的所有 `fade*` 共用同一个世界包围盒、同一个「人在里面」的矩形，一起淡出，和程序房子的 `up` 部分一致。
  - **预热**：`_warm_up` 在那三帧里把带状态物件的所有状态节点都显示出来，之后还原，免得第一次切状态才编译着色器卡一下。**代价**：它和主视口共用一个世界，所以这三帧里镜头里若正好有这些物件，会闪一下「所有状态叠在一起」。线上没有 `scene` 条目时不存在这件事；有了以后如果碍眼，改成用独立的 `World3D` 做预热。
  - 持久：服务端数据给出的状态（`_prop_want`）和调试强行状态（`_prop_forced`）不随地图重建清空，重建后恢复。
- `main.gd`（只加了三处）：`_apply_me` 里一行 `world.sync_object_states(cur_scene, here.get("objects"))`；`_on_ui` 里的 `debug_prop_state` 事件；`_push_debug` 里的 `"props"` 字段。
- **建筑的替换入口**：`world.gd` 的 `_add_building()` 先查外观表有没有 `building.<区域编号>` 且带 `scene`；有就实例化它（`_add_scene_building`）代替程序生成的房子，`base*` 常显，`fade*` 登记淡出（人在外框里整栋淡掉，挡在镜头和人之间淡到 0.1），门口的暖光池照旧。没有这种条目时走原来的代码，一个字节都没动。程序房子的窗口光晕（`res["glows"]`）和门灯在 scene 版本里不画，要的话做进资产的发光顶点。

## 调试钩子（只在 `?debug=1` 下）

- 地址栏 `?debug=1&props=sample`：把 `prop.stove` 指到 `station_sample`、把 `building.kitchen` 指到 `building_sample`（`debug_flags.gd` 的 `apply_props`，由 `bridge.gd` 读地址栏、`world.build()` 开头经 `art.apply_debug()` 叠到外观表上；叠加顺序是默认表、`art_private`、调试，最后叠）。不带 `?debug=1` 的页面无视 `props` 参数。**默认的 `art_table.json` 不指向任何样件**（单测里有断言）。
- `window.__town.props`：每个带状态物件的 `{id, kind, state, states, forced}`；没有带状态的物件时是空数组。
- `window.__town.setPropState(编号, 状态名)`：强行切状态（服务端数据刷新不会盖回去）；状态名传空串解除，回到服务端数据。和 `pickStub`、`hideNpcs` 一样挂在 `hud.js` 的 `debugSet` 里（`hud.js` 每 100 毫秒整个换一遍 `window.__town`，函数跟着重挂），发 `debug_prop_state` 事件给 `main.gd`。

## 怎么做一件新资产

1. 建目录 `client/art_source/kits/<套件>/<资产编号>/`，写 `build.py`（照 `kits/sample/station_sample/build.py`）：
   ```python
   import os, sys
   sys.dont_write_bytecode = True
   sys.path.insert(0, os.path.join(os.path.dirname(os.path.abspath(__file__)), "..", "..", "..", "tools"))
   import kit_lib as K
   def build():
       K.begin("<资产编号>", "<套件>", 1, "自制（本脚本生成）", "client/art_source/kits/<套件>/<资产编号>/build.py")
       K.box("base_body", (0, 0.4, 0), (2.0, 0.8, 1.5), (0.55, 0.38, 0.25))      # 名字、中心、尺寸、颜色
       K.empty("state_idle")                                                      # 必须有
       K.empty("anchor_use_1", (0, 0, 1.5), yaw=180)
       K.cyl("state_busy_flame", (0, 0.9, 0), 0.1, 0, 0.2, (1.0, 0.55, 0.16), glow=0.9)
       K.export(K.out_path_from_argv())                                          # 先查约定，不合格直接报错退出
   K.run(build)
   ```
   几何函数：`box`、`cyl`（圆台 / 圆锥）、`gable_x`（双坡屋顶）、`mesh`（自己给顶点和面）；`empty`（锚点和空状态）；`animate`（给某个物件做一段位置或旋转动画，动画名按上面的规则）。手工做的 `.blend` 也放在同一个目录，配一个只负责按同样规则命名并调 `K.export` 的脚本（`.blend` 单个先控制在几 MB 以内，见 `docs/art/standard.md`）。
2. `bash client/art_source/build_kits.sh <套件>/<资产编号>`：生成 GLB、让 Godot 导入、生成 `.tscn` 和 `manifest.json`、跑校验。红了就按输出改。
3. 把生成物一起提交：`.glb`、`.glb.import`、`.tscn`、`manifest.json`（GLB 的 `.import` 要入库，`client/town/.godot/` 不入库，和现有模型一样）。
4. 登记进 `client/ASSETS.md`（来源、许可、脚本）。
5. 让游戏用它：外观表（`art_table.json`，或不进仓库的 `art_private/art_table.json`）加一条 `"prop.<物件种类>": {"scene": "res://assets/kits/<套件>/<资产编号>/<资产编号>.tscn"}`（建筑是 `"building.<区域编号>"`）。在这之前可以用 `?debug=1&props=sample` 的写法临时看，把要看的条目加到 `debug_flags.gd` 的 `SAMPLE_PROPS`。
6. 新的状态名不在四个以内时：清单里可以有，`stateful_prop.gd` 也认，但要在 `prop_state.gd` 里加「服务端数据 -> 状态名」的映射，否则永远进不去。

**重建的稳定性**：同样的 `build.py` 在同一个 Blender 版本下导出的 GLB 逐字节相同，包装场景和清单也是；换 Blender 版本，GLB 里的 `generator` 字符串和清单的 `source.blender` 会变。`.glb.import` 里是 GLB 的 uid：重建时只覆盖 `.glb`、`.tscn`、`manifest.json`，不要删 `.import`（删了 Godot 重导会换一个 uid）。包装场景的外部引用只写路径、不写 uid，所以换 uid 也不会让它变。
