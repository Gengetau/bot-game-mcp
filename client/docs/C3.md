# C3：走到游戏桌入座，玩一局数字炸弹

玩家在街机厅（arcade）走到游戏桌边，凑人、开局、玩完一局数字炸弹（number_bomb），全程用网页客户端完成；桌面键盘和手机屏幕小键盘都能玩。只做客户端，没有动 `packages/`。

## 2. 钩子与归属

- `event_types`：`activity`、`game_started`、`game`、`game_out`、`game_ended`；`wants_tick` 为真（4Hz）。
- `on_pick(kind, id, src)`：只认 `kind == "obj"` 且在 `/me.here.tables` 里的物件，其余一律返回 false。点击和 E 键走同一个入口（`src` 不参与分支）。已站在落脚点（离桌心不超过 2 米）：返回 true 什么都不做；刚点过同一张桌子且还在走：返回 true 不重复发导航（连按两下 E 只走一次）；否则挑落脚点并走过去。
- 选落脚点（`pick_seat`）：别的角色 0.6 米内算占着，在没被占的里面取离自己最近的，全占了取最近的。
- `blocks_input`：局中返回「对局中，先打完这一局（或点「离开这局」）。」，其余为空；局结束、主动退出、`on_leave`、`/me` 里没有 game 之后都清掉。与 C2 互斥。
- `actions`：局中只有「离开这局」（二次确认）；局外只在 `near` 有效且站在桌边时出「开一局：数字炸弹」`f:game:propose:<桌>`、「加入」`f:game:join:<活动>`、「开始」`f:game:start:<活动>`、「散桌 / 离开这桌」`f:game:leave`。只删游戏桌自己的 `go:<桌>`。
- `tags`：桌牌 `g:<桌>`，写「数字炸弹 · 等人 1/8（至少 2 人）」（任务书写的 1/2 是最少人数，服务端的人数上限是 8，按服务端的 max 显示），坐标只在 Godot 内现算，网页只拿屏幕比例。
- 没有 `setUnread`；不新增任何浏览器存储键。

## 3. 动作与失败处理

- 所有动作走 `ctx.act_once`（不睡眠重试，网络失败时保留同一个请求号，再点一次是同一个请求）。
- `too_far`：只自动走向桌子的落脚点，**不重发动作**，提示「到了再点一次」。
- `start_game` 返回 `dropped` 名单时提示「X 不在桌边，没有加入这一局」；被丢出的人收到「开局的时候你不在桌边，没有加入这一局。」。`not_enough` 整条回滚，名单不变。
- 局内视图：事件只是通知，权威是 `GET /game`；按 `(phase_id, 最后事件 seq)` 防乱序，倒计时归零约 1.5 秒后补读一次，每 20 秒兜底读一次；`phase_stale` 后立刻刷新。
- 自己点「离开这局」会记下活动号，之后到来的 `game_ended` 不弹结果卡（`endedIgnored`）。退出请求网络失败时这个记号撤掉（请求可能没到服务端，局之后自然结束要照常弹卡；再点一次是同一个请求号，记号重新记上）；退出请求在路上时局自然结束、退出又失败（比如 `context_stale`），把被抑制的那条 `game_ended` 补弹成结果卡。
- 已结束 / 退出 / 清掉的活动号记在 `_ended_aids`：迟到的旧 `/me`（还带着 game）不能把局复活，也不会抹掉真实的结果卡；追读的 `/me` 没有 game 时不再推断出奖励为 0 的卡。推断出来的卡（kind unknown）之后若来了真实的 `game_ended`，用它覆盖（补上奖励和输赢）。
- `_left_acts`（自己点了离开的桌，不再对自己弹「这一桌散了」）在重新加入同一桌成功时清掉。
- 结果卡先用事件里的话，再拉匿名公开投影 `/public/game/<id>` 补原因和每个人的结局；关闭后（或约 20 秒自动收起）底栏恢复。

## 4. 网页层

- 局中 `body[data-game="1"]` 藏掉 `#actions`、`#stopBtn`、`#homeBtn`、`#destBtn`，保留 `#dockBtn`；收起、重置、`on_leave` 一定清除（C4 的居民卡靠它在局中隐藏）。
- 桌面用文本框（Enter 提交、上下箭头加减 1、Esc 失焦、只收数字）；触屏用 3x4 屏幕小键盘 + 只读显示框 + 「取中间」。输入框用 `readonly` + `aria-disabled`，不用 `disabled`。本地先校验非数字和越界，不发请求。
- 横屏矮屏（横屏且高度不超过 520 像素）：左右两栏，左边是局面，右边是输入。右栏最窄 292 像素，放得下一排 6 个不小于 44 像素的数字键（6 x 44 + 5 x 4 = 284）；面板宽 `min(600px, 86vw)`。
- 确认条开着时局被动结束（`mode` 变成结果卡 / 无）：收起确认条的同时恢复「离开这局」按钮（`closeConfirm`），否则下一局没有退出入口。
- 轮到自己时桌面自动聚焦输入框：焦点不在别的输入类元素里就聚焦（画布、按钮、页面本身都不算占着焦点）。触屏设备（`coarse`）的输入框只读、不弹系统键盘，但同样自动聚焦，数字键、退格、Enter、Esc 由输入框的 keydown 接手，接了实体键盘的平板也能打；焦点在输入框上，dock 的全局 Enter 就不会去开聊天。
- 横屏矮屏：玩家一排放不下就横向滚、猜数历史最多露两行；右侧栏打开（`body[data-dock="side"][data-dock-open="1"]`）时面板宽度只用侧栏左边的地方，改成单栏、收起猜数历史、纸板内边距和间距收紧，空着的提示行不占高度（有提示时面板往上长一点），最大高度减去底栏占的位置并给顶栏留出 60 像素。
- 全部文字在 `[data-bank]` 里，玩家名与服务端文字只走 `textContent`。

### 统筹复核时补的三处（11-15）

读评审修复的代码时发现的，都在 `game.gd`，各有无头单测（`game_feature_test.gd` 现在 41 项；把 `game.gd` 换回补之前的版本，新加的三个用例里 9 项变红）：

- **推断出来的「结束」不登记进 `_ended_aids`。** 评审修复为了挡「迟到的旧 /me 把已结束的局复活」，在 `_clear_game` 里统一登记了结束的活动号；但 `_game_vanished`（/me 里没有 game 了，推断为结束）也走 `_clear_game`，而推断可能是错的：开局那一刻还在路上的旧 /me，慢网时会晚于 `START_HOLD_S`（2.5 秒）才到。登记之后，下一份带着 game 的 /me 被永远忽略，人被锁在局外（面板不回来、服务端认为他在局里所以也走不了），直到这一局结束。现在只在确实知道结束时登记（收到 `game_ended`、退出成功），推断错了下一份 /me 就接回来。/me 的读取在 `main._refresh_me` 里是串行的，「没有 game 的 /me 之后又来一份带着同一局的旧 /me」不会发生，所以推断这条路不需要登记。
- **推断卡被公开投影补全之后，真实的 `game_ended` 仍然覆盖它。** 评审修复按 `kind == "unknown"` 认推断卡，但 `_pull_public` 读回公开投影后会把 `kind` 改成输 / 赢 / 中止，之后到的真实事件就被当成重复丢掉，卡上的奖励一直是 0。改成结果卡自己带 `inferred` 记号。
- **退出请求号只对同一局有效。** 退出时网络失败会留着请求号（同一局再点一次是同一个请求，不会退两次）。这个请求号以前不分局：上一次请求若其实到了服务端（只是回执丢了），之后另一局里点「离开这局」会带着旧请求号，服务端把上一局的回执原样还回来，客户端以为退出成功，实际上人还在局里。现在换了一局就换新的请求号。

这三处补完之后，请另一位同事只读地做了一遍对抗式评审（按代码推演输入序列，不跑测试），又补了两处（单测加到 50 项，见 `game_feature_test.gd` 末尾两个用例；换回补之前的 `game.gd`，其中 3 项变红）：

- **退出请求在路上时，一份没有 game 的 /me 抢先到。** 这份 /me（退出提交之后才发出的）经 `_game_vanished` 把「我退出了」的记号用掉、不弹卡；随后退出成功的回执到了，却没有把记号补回去，之后到的 `game_ended` 就给主动退出的人弹了结果卡。现在退出成功时，只要这一局的 `game_ended` 还没到过，就把记号补上。（要退出的回执比一份完整的 /me 往返还慢才会出现，比如回执那个连接丢了包。）
- **结束过的局一律不再认。** `_enter_game` 以前只在「不在局中」时才查 `_ended_aids`；上一局确实结束、下一局已经开始时，一份还带着上一局的旧 /me 能把面板换回上一局（下一份 /me 会再换回来）。活动号不复用，去掉了那个前提。

那位同事另外看到、没有改的：离桌请求网络失败时「我离开过这一桌」的记号不撤，之后这一桌因超时散掉时少一句「这一桌散了」（撤掉则请求其实到了的时候会多一句，取舍同退出）。

留给之后的（记在进度记录里）：慢网（往返超过 2.5 秒）时开局瞬间可能闪一下推断的结果卡，下一份 /me 自愈，要根治得让 `on_me` 知道这份 /me 是开局之前发出的；退出请求「到了服务端但回执丢了」时，主动退出的人会看到一张结果卡；大厅动作（离桌、开桌）留着的请求号同样不分桌，后果是多点一次（下一份 /me 纠正），没有改。
