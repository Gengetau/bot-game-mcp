# C1b：全镇公屏、头顶气泡、静音

接在 C1a 的面板底座上：页签「全镇」（读、写、静音）和附近聊天的头顶气泡。服务端契约见 `docs/TOWN.md` 与 `packages/engine/src/world/chat.ts`，这一段没有动服务端。

## 1. 结构

| 文件 | 作用 |
| --- | --- |
| `client/town/scripts/features/town.gd` | Godot 一侧：读（分页、WS 帧、断线补读、resync）、写（`say_town` 与回执）、静音（`update_profile {muteTownChat}`）。状态只放内存 |
| `client/town/scripts/features/bubbles.gd` | 头顶气泡：只听「附近聊天」，用 hud 的 `tags()` 钩子出 `.tag.b` |
| `client/town/scripts/features/ctx.gd` | 只在 C1b 分区加了 `navigate_to_place`（「走过去」按钮用） |
| `client/town/web/mod/town.html / .js / .css` | 页签模板与文字库、行装饰（类型小牌、@ 高亮、走过去）、静音按钮、读取状态条 |
| `client/town/web/mod/bubbles.css` | 气泡样式 |
| `scripts/e2e/lib/town.mjs`、`steps/30-chat-town.mjs` | 端到端 |

消息列表和输入栏复用 `00-chatkit.js`（冻结，没改）。Godot 给每条消息一个本地整数序号 `ord`（追新 `++_hi`，读更早 `--_lo`）交给网页当 id；服务端游标是不透明的，既不比较也不存。

## 2. 行为

读：
- 进入时 `GET /town-chat?limit=50` 读最近一页；hello 带 `townChat.cursor`，与本地 `_after` 一致就不读，不一致就 `?after=` 补读（每页 100，最多 10 页，超了或返回 `resync:true` 就整体重读，草稿保留）。
- `_after` 只由 HTTP 页游标或 WS 帧推进，且只有帧里最后一条是新的（或经回执认领的）才推进；发送回执永远不推进它。
- 同步期间收到的帧先缓冲，读完再按 sid 去重合并；读完后再对一次 hello 水位。
- 「看更早的话」：`before` 游标，`limit = min(页大小, 200 - 已有)`；列表上限 200 条，到顶后显示提示；读完后把原来看着的那一行放回原处。
- 静音时新话一律按历史处理，不计未读；@ 判定为「非自己的话里含 `@` + 我的名字」（NFKC、小写、去零宽字符，名字不足 2 个字符不判）。

写：
- 类型（闲聊 / 组织活动 / 求助）三块小木牌，后两种可选地点（七个公共地点之一）。
- 本地先查：空、超长（`chatMaxChars`）、对局中、只读（控制权不在本页）。服务端的拒绝（限流带倒计时、重复、不在场、控制权丢失）映射成固定文字。网络失败保留同一个 rid，重试不会重复发。
- 自己发的话先等 WS 帧认领（2 秒兜底再按回执补上），所以不会出现两行。

走过去：活动 / 求助带地点时行内有按钮，发 `navigate {to: 地点}`，只放白名单地点编号。

静音：整个公屏一个开关，没有按人屏蔽。状态以 `/me` 的 `settings.muteTownChat` 为准；换人、离开时全部复位。

气泡：
- 只听附近聊天，全镇公屏永不冒泡。说话人找不到（`_anchor` 返回空）或消息比 8 秒还旧（断线续传补回来的）不冒泡。
- 显示时长 `clamp(2200 + 80·字数, 3000, 6500)` 毫秒，最多同时 6 个，文字压平空白、超过 28 个字符截断。
- 位置只在 `bubbles.gd::_anchor` 一处决定（说话人在哪、多高）；之后 C6 接 NPC 只改这个函数。
- 气泡是 hud 的 `.tag.b`，用 CSS `margin-top:-26px` 放在名牌上方（不是 z-index），淡入只动 opacity（动 transform 会盖掉 hud 的内联位置）。

## 3. 观感

范围牌是灰蓝（附近是木色），一眼分清范围；组织活动 / 求助是便签黄小牌，@ 我的行有暖橙细边。手机抽屉里隐藏规则提示、压紧行距，保证能看到至少 4 条消息；软键盘出现时隐藏规则、类型牌和状态条，只留输入栏。点按目标都不小于 40×32，地点下拉字号 16px（避免 iOS 聚焦放大）。

## 4. 对规格的取舍与修正

- 静音走 `update_profile`，没有做按人屏蔽（规格要求如此）。
- 不把服务端游标存浏览器（规格：不用浏览器存储）；刷新后就是重读最近一页。
- hello 里的 `_left` 守卫：`on_leave` 之后、下一次 `on_enter` 之前，hello 不触发读取。没有它，离开再换人登录时会发出一个已无会话的 `GET /town-chat`，得到未声明的 401（e2e 全程检查抓到的，加守卫后消失）。
- 「4 条消息行」的断言用行高中位数：个别长话折行不该决定布局是否合格。

## 5. 真机待办（无头浏览器验证不了）

- 真手机上软键盘弹出后的视口与输入栏位置（e2e 只用 `data-kb` 模拟）。
- iOS 上地点下拉的原生选择器观感；Android 上的长按选字。
- 屏幕阅读器读「全镇」页签的未读小点与 `aria-live` 状态条。
- 真实弱网下的重试节奏（e2e 只用拦截的 429 和断线开关）。
- 气泡在真机低端 GPU 上与名牌的叠放。

## 6. 已知缺口与没做的

- 骨架缺陷（需先合并的补丁，不在 C1b 改）：手机抽屉里 `#dockGrip`（dock.css：高 44px、z-index 2）盖住整条页签，Playwright 真实点击页签会一直超时，真人点页签也会被当成点把手而收起面板。建议把把手缩到不盖页签的区域或让页签排除在把手之外。e2e 里 `lib/town.mjs::openTown` 在抽屉布局下改为对页签派发 click 绕过。
- 气泡之间不避让：两位居民站得很近（截图里两人几乎重叠）时，两个气泡会叠在一起，后一个的文字可能被前一个或名牌盖住。每个气泡只相对自己的名牌定位。真实场景里人通常不会完全重叠，留作后续（可在 `_anchor` 一处加错位）。
- 没做：按人屏蔽、公屏的撤回 / 举报、气泡里的类型图标、NPC 头顶气泡（C6）。
- 对局中公屏只看不发的真实对局断言由 C3 的 50.45 补；服务端侧已有 `chat-direction.test.ts`。
- 30.75 的 resync 重建没能做出红灯，见下。
