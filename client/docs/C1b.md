# C1b：全镇公屏、头顶气泡、静音

接在 C1a 的面板底座上：页签「全镇」（读、写、静音）和附近聊天的头顶气泡。服务端契约见 `docs/TOWN.md` 与 `packages/engine/src/world/chat.ts`，这一段没有动服务端。

## 1. 结构

| 文件 | 作用 |
| --- | --- |
| `client/town/scripts/features/town.gd` | Godot 一侧：读（分页、WS 帧、断线补读、resync）、写（`say_town` 与回执）、静音（`update_profile {muteTownChat}`）。状态只放内存 |
| `client/town/scripts/features/bubbles.gd` | 头顶气泡：只听「附近聊天」，用 hud 的 `tags()` 钩子出 `.tag.b` |
| `client/town/scripts/features/bubble_layout.gd` | 气泡排版（纯函数）：估算气泡与名牌的屏幕矩形、错开、平滑、顶部放不下就不画；无头单测见 `client/tests/bubble_layout_test.gd` |
| `client/tests/town_logic_test.gd`、`bubble_layout_test.gd`、`client/tools/unit.sh`（`npm run client:unit`） | 无头 Godot 单测（不起浏览器、不用导出，每个文件不到一秒）：公屏读写与同步的时序（读更早与追新并发、回执与回声、同步期间缓冲、resync、离开……）、气泡排版 |
| `client/town/scripts/features/ctx.gd` | 只在 C1b 分区加了 `navigate_to_place`（「走过去」按钮用） |
| `client/town/web/mod/town.html / .js / .css` | 页签模板与文字库、行装饰（类型小牌、@ 高亮、走过去）、静音按钮、读取状态条 |
| `client/town/web/mod/bubbles.css` | 气泡样式 |
| `scripts/e2e/lib/town.mjs`、`steps/30-chat-town.mjs` | 端到端 |

消息列表和输入栏复用 `00-chatkit.js`。评审修复时给它加了一个只增不改的接口 `kit.clearList()`（只清列表与未读，不动发送中状态、限流倒计时、提示、ArrowUp 记录、草稿），整体重读（rebuild）改用它，不再走完整的 `kit.reset()`；其余部分没动。Godot 给每条消息一个本地整数序号 `ord`（追新 `++_hi`，读更早 `--_lo`）交给网页当 id；服务端游标是不透明的，既不比较也不存。

## 2. 行为

读：
- 进入时 `GET /town-chat?limit=50` 读最近一页；hello 带 `townChat.cursor`，与本地 `_after` 一致就不读，不一致就 `?after=` 补读（每页 100，最多 10 页，超了或返回 `resync:true` 就整体重读，草稿保留）。
- `_after` 只由 HTTP 页游标或 WS 帧推进，且只有帧里最后一条是新的（或经回执认领的）才推进；发送回执永远不推进它。
- 同步期间收到的帧先缓冲，读完再按 sid 去重合并；读完后再对一次 hello 水位。
- 「看更早的话」：`before` 游标，`limit = min(页大小, 200 - 已有)`；列表上限 200 条，到顶后显示提示；读完后把原来看着的那一行放回原处。请求在途时追新可能把列表填满、甚至因封顶弹掉最旧的几条：回来后只收得下 `200 - 现有` 条（取紧挨着现在最前面的那几条，`_older` 从截断处接着读），一条都放不下就丢掉这一页，不会在中间留断档。
- 回执补进列表的话记在 `_rcpt`；HTTP 补读（最近一页或 `?after=`）读到同一条时清掉记录，因为页的游标已经把 `_after` 推过它了，之后晚到的回声帧不会把 `_after` 拨回更旧的值。
- `on_leave` 之后、下一次 `on_enter` 之前 `tick` 什么都不推（登出状态下不显示「正在读公屏…」）。
- 静音时新话一律按历史处理，不计未读；@ 判定为「非自己的话里含 `@` + 我的名字」（NFKC、小写、去零宽字符，名字不足 2 个字符不判）。

写：
- 类型（闲聊 / 组织活动 / 求助）三块小木牌，后两种可选地点（七个公共地点之一）。
- 本地先查：空、超长（`chatMaxChars`）、对局中、只读（控制权不在本页）。服务端的拒绝（限流带倒计时、重复、不在场、控制权丢失）映射成固定文字。网络失败保留同一个 rid，重试不会重复发。
- 自己发的话先等 WS 帧认领（2 秒兜底再按回执补上），所以不会出现两行。

走过去：活动 / 求助带地点时行内有按钮，发 `navigate {to: 地点}`，只放白名单地点编号。

静音：整个公屏一个开关，没有按人屏蔽。状态以 `/me` 的 `settings.muteTownChat` 为准；换人、离开时全部复位。

气泡：
- 只听附近聊天，全镇公屏永不冒泡。说话人找不到（`_anchor` 返回空）或消息比 8 秒还旧（断线续传补回来的）不冒泡。
- 显示时长 `clamp(2200 + 80·字数, 3000, 6500)` 毫秒，最多同时 6 个，文字压平空白、超过 28 个字符截断。
- 位置只在 `bubbles.gd::_anchor` 一处决定（说话人在哪、多高）；之后 C6 接 NPC 只改这个函数。
- 气泡是 hud 的 `.tag.b`，用 CSS `margin-top:-26px` 放在名牌上方（不是 z-index），淡入只动 opacity（动 transform 会盖掉 hud 的内联位置）。
- 排版（`bubble_layout.gd`，CSS 像素；Godot 的画布是物理像素，要除以 `screen_get_scale()`）：按字数估气泡的宽高（13px 字号，最大宽 `min(60vw, 220px)`，两行约 43px），按「屏幕上更靠下（离镜头近）的人先放」排序，每个气泡往上抬到不压已放好的气泡、也不压别人的名牌（名牌层级高于气泡，hud 的行内 z-index 压不过样式表，只能靠位置错开）。谁往上让只看屏幕位置，不看谁先说话。抬高量只是目标值，显示值用指数趋近平滑（人走动穿过阈值、前一个气泡过期时不再一帧跳一截）。可见部分的上沿高于 60 CSS 像素（顶栏之下）就这一帧不画，人走下来就出现，不会被顶栏盖住或被 hud 的钳位压成一叠。
- `debug().shown_by`：累计「给谁冒过几次气泡」，端到端用它证明「没有为某人冒过气泡」，不受气泡 3 秒寿命影响。

## 3. 观感

范围牌是灰蓝（附近是木色），一眼分清范围；组织活动 / 求助是便签黄小牌，@ 我的行有暖橙细边。手机抽屉里隐藏规则提示、压紧行距，保证能看到至少 4 条消息；软键盘出现时隐藏规则、类型牌和状态条，只留输入栏。点按目标都不小于 40×32，地点下拉字号 16px（避免 iOS 聚焦放大）。

## 4. 对规格的取舍与修正

- 静音走 `update_profile`，没有做按人屏蔽（规格要求如此）。
- 不把服务端游标存浏览器（规格：不用浏览器存储）；刷新后就是重读最近一页。
- hello 里的 `_left` 守卫：`on_leave` 之后、下一次 `on_enter` 之前，hello 不触发读取。没有它，离开再换人登录时会发出一个已无会话的 `GET /town-chat`，得到未声明的 401（e2e 全程检查抓到的，加守卫后消失）。
- 「4 条消息行」的断言用行高中位数：个别长话折行不该决定布局是否合格。

## 5. 真机待办（无头浏览器验证不了）

- 真手机上软键盘弹出后的视口与输入栏位置（e2e 只用 `data-kb` 模拟）。
- iOS 上地点下拉的原生选择器观感；Android 上的长按选字。
- 屏幕阅读器读「全镇」页签的未读小点与 `aria-live` 状态条。
- 真实弱网下的重试节奏（e2e 只用拦截的 429 和断线开关）。
- 气泡在真机低端 GPU 上与名牌的叠放。

## 6. 已知缺口与没做的

- 骨架缺陷（需统筹先合并的补丁，不在 C1b 改，本段规定不动 dock.css）：手机抽屉里 `#dockGrip`（dock.css：`left:0; right:56px; top:0; height:44px; z-index:2`）盖住整条页签（`#dockTabs` 高 40px、没有 z-index），dock.js 的把手在 pointerup 位移 < 8px 时 `close()`。所以手机上点「全镇」页签（点击落在把手上）会收起面板，而不是切页签（除非上次就停在「全镇」）。已用代码核对；e2e 里 `lib/town.mjs::openTown` 在抽屉布局下改为对页签派发 click 绕过，所以手机端「切到全镇」目前没有任何真实点击的断言。建议补丁：`#dockTabs { z-index: 3 }`（高于把手的 2，低于关闭钮的 3 之后的覆盖关系不变），或把把手缩到只盖顶部 12px 的拖条；补丁合并后删掉 `openTown` 的 `dispatchEvent` 分支、改用真实点击（或 `touchscreen.tap`）。**补丁合并前，不要把本段手机端的页签切换当作已验证。**
- 气泡避让见第 2 节「排版」。已知局限：气泡的小三角固定在气泡中间（CSS），被错开到别处的气泡的三角不一定指向说话人；hud 一次只认 `x`、`y`、`n`、`k`、`sel`，三角偏移要改 hud.js，不在本段范围。屏幕上方放不下（顶栏之下）时这一帧不画。尺寸是按字数估的（拉丁字母按 7.5px、汉字 13px），不是量出来的，所以留了 2px 的缝；真机字体不同时可能有几个像素的偏差。
- 没做：按人屏蔽、公屏的撤回 / 举报、气泡里的类型图标、NPC 头顶气泡（C6）。
- 对局中公屏只看不发的真实对局断言由 C3 的 50.45 补；服务端侧已有 `chat-direction.test.ts`。

## 7. 验证记录

评审修复这一轮（生命周期同步、气泡排布、隐私与测试三组问题）的实测结果。

**截图**：自己看过 5 张（`client/demo/30-*`、`31-*`）。桌面白天 / 傍晚全镇页签、手机抽屉都清楚；气泡现在按屏幕位置从前往后排，不压别人的名牌，两人站得近时不再互相遮挡。

**无头单测**（`npm run client:unit`，`client/tests/town_logic_test.gd` 47 条、`bubble_layout_test.gd` 23 条，全绿）。逐条破坏后各自变红，对应关系见 `scripts/e2e/steps/30-chat-town.mjs` 末尾的注释块。要点：回执不推进 `_after`、同步期间帧缓冲、水位相等不发请求、读更早按剩余位置截断、older 序号方向、离开清空、离开后 tick 不推 state、HTTP 补读清 `_rcpt`、`_send` 本地检查；名牌当障碍、按屏幕位置排序、顶部隐藏、平滑、宽气泡相交。

**端到端**：
- 评审修复前的构建上跑新断言：30.76（整体重读后倒计时 / 提示 / 历史被清）红，31.5（气泡互相重叠、压在别人名牌上）红。修复后同一组全绿。
- 破坏网页层：`mentionsMe` 恒真 -> 32 红；`textContent` 改 `innerHTML` -> 20.8 红；`startCooldown` 改回旧写法 -> 30.76 红。改回后全绿。
- 最后一遍 `--only=1,4.5,20,chat-town`：除旧步骤 20.95 外全绿（全程检查无问题）。20.95 的红是 `window.__town` 快照滞后（0.1 到 0.5 秒才推一次）导致的「换名重进应是另一位居民」，旧构建上同样出现；已改成先 `until` 等快照里的自己变化，断言不变。
- 旧 20.3 的根因找到并修了：chatkit 倒计时少数一拍（1 秒倒计时时发送钮没禁用），不是负载时序；30.76 有确定性断言。旧 4.5 两遍都绿。
- 旧步骤 15 的红由统筹另行处理，本段没有碰。

**没做的（如实）**：
- 手机 `#dockGrip` 盖住页签：要改 `dock.css`，规格禁止，补丁建议写在第 6 节。
- 限流提示改固定文字（J3）、JS 一侧地点白名单、Godot 一侧「公屏帧也触发气泡」的破坏验证没有做；改 GDScript 的端到端破坏要重新导出（约 2 分钟一次）。30.75 的 resync 只靠单测抓两处 `_clear_list`，端到端没有对着去掉两处的导出重跑。
- 气泡的小尾巴固定在气泡中央，不一定指向说话人（要改 `hud.js`，不在范围）；布局用的宽高是估算值，真机可能差几个像素；屏幕顶部的情形只有单测覆盖，没有端到端。
