# C2：共同活动（一起喝茶、读书）

本段在三维客户端里把栖灯镇的「多人公共物件活动」做通：茶桌（喝茶，2 到 4 人）、藏书架（读书，1 到 4 人，先等人）、灶台、花箱（通用代码自然覆盖，没有专门文案和步骤）。玩家走到桌边、约人、别人加入、开始、中途走开、结束，界面上看得见谁在等、还差几人、进行中的剩余时间。单人动作（main 的 `do:` 按钮）和「停下手上的事」不重复做。本段没有改 `packages/`，没有改 `main.gd`、`hud.js`、`dock.js`、`feature.gd`、`hub.gd`、`manifest.gd`、`client-e2e.mjs` 等冻结文件。

| 文件 | 作用 |

| `client/town/scripts/features/activity_logic.gd` | 纯逻辑：拦截状态机 `gate`、选座 `pick_seat`、桌牌与提示文字、名单差异。不读场景、不取时间，单测在 `client/tests/activity_logic_test.gd`（`npm run client:unit`） |

| `scripts/e2e/steps/40-activity.mjs`、`scripts/e2e/lib/activity.mjs` | 端到端步骤 40 到 40.95 与小工具 |

### 默认页签与文件名（接缝上的一个坑）

`dock.js` 在每个模块注册时只要「当前没有有效页签」就把排在最前的设为当前页签，之后注册的不会改它；而 `mod/*.js` 按文件名字母序拼接，所以第一个注册的模块就成了默认页签。本段最初的文件叫 `activity.js`，字母序在 `nearby.js` 前面，结果每个新玩家打开面板看到的是「一起」而不是「附近」，20 号步骤整段红（输入框不可见）。解决：本段的网页文件改名为 `together.*`（排在 nearby、people 之后），不碰 `dock.js`。这是 `dock.js` 的缺陷：它应该在每次注册后按 `data-order` 重选（没有记住的页签时选 `order[0]`）。后面的 C5（`mail.*`）、将来任何字母序在 `nearby` 之前的模块都会再踩一次，建议统筹在 `dock.js` 里修（`else if` 分支改成「没有记住的页签就取 `order[0]`」），修了之后文件名就不再要紧。

## 2. 玩家看到的

1. 走进茶馆，离茶桌远时 `#actions` 里没有共同活动按钮；打开面板的「一起」页签能看到本处的桌子（靠窗的茶桌、里间的茶桌：空着）。
2. 点茶桌（点击或 E 键）：不走服务器默认的「最近座位」，客户端挑一个没人站的座位走过去（4）。走到后坐下，`#actions` 出现「约人一起喝茶」（副标题是桌名）。
3. 点它：发 `start_interaction`（`wait: true`）。按钮变灰「等人中 · 还差 1 人」；桌子上方出现桌牌「喝茶 · 等人 1/2」；main 的状态条出现「正在：一起喝茶」；页签的「我的这一桌」卡显示谁在座、还差几人、再等多久散场（报名最长保留 `activityLobbyTtlMs`）。
4. 别人走进茶馆，页签里看到「靠窗的茶桌 · 等人 1/2」，离桌子远时写「走到桌边才能加入」、没有「加入」按钮；走到桌边（也是点桌子选座）才出现「加入」。
5. 人数够了（达到 min）发起人的按钮变亮成「开始」，桌牌变「可开始 2/4」；非发起人的页签写「等 某某 开始」。人满自动开始（弹「开始了，大约 N 分钟。」）。
6. 开始后桌牌「喝茶 · 2 人」，页签变进行中：倒计时、进度条（服务器给的 `startedAt` 与 `endsAt` 算出来）。
7. 走开：点地、方向键、地点、回家都会先被拦下并提示一次（「喝茶还没结束，现在走开就退出，没有这次的收获。再试一次就走。」），隔一会儿再试才真的走。留下的人看到「某某 走开了。」，活动照常继续；发起人在等人阶段走开，整桌取消，别人看到「这一桌散了：发起人走开了」（原因是服务器的原文）。
8. 到时间服务器结算：main 弹出收获，桌牌消失、角色站起，页签留一张「刚才」小卡（收获文字），直到下一次活动或离开小镇。
9. 读书：一个人读用 main 原有的「读书」按钮；多一个「约人读书」（先等人，一人也能开始）。读书不坐下。

## 3. 钩子与访问器

- 事件：只订阅 `interaction`、`interaction_done`。`on_event(ev)` 的载荷在 `ev.data`。
- `ctx.gd` 的 C2 分区新增：`object_info(oid)`（`world.find_object`，含 `anchors`、`center`、`pos`、`kind`、`name`）、`walk_to(to, label, mark)`（走 `main._do_navigate`，管续租、序号栅栏、落点标记、拦截；顺手清 `selected_obj`）、`near_ok(oid)`（`near_valid` 且 `_is_near`）、`invalidate_near()`（`too_far` 之后）、`refresh_me_wait()`，评审修复又加了 `key_press_edge()`（方向键这一次按下的编号，见 5）、`nav_gen()`（main 的导航代号，比较前后两次就知道中间有没有改过道）和 `next_frame()`（等下一帧，动作之后等 `/me` 追上时用）。没有直接发 `navigate`，也没有伸手进 main。
- `actions(out)`：按钮 id 一律 `f:activity:<动词>:<参数>`（`invite` 参数是物件编号，`join` / `begin` 是活动编号，`wait` / `full` / `running` 是灰按钮）。出现条件与 `main._build_actions` 一致：够得着（`near_ok`）、自己不在走、不在小游戏里、已在游戏中。只删 main 追加的、属于自己这类物件（`action.max>=2`）且已经够得着的 `busy:<oid>`（「使用中」，藏书架有活动时 main 会加）和 `go:<oid>`（「走过去」）两种条目，其余一律不动。
- `on_pick(kind, id)`：点击和 E 键进来结果一样（`main._do_interact` 与 `main._on_tap` 都先问 `features.on_pick`）。只认 `kind == obj` 且在 `/me` 的 `here.objects` 里、`action.max>=2`、使用位不止一个；游戏桌在 `here.tables`，天然不是我的（归 C3）。已经坐在这张桌的某个座位上（离使用位不大于 0.5 米）返回 true 并什么都不做（不发导航、不记选中、不弹「走过去」）。防重入：同一张桌的导航在发、刚发完（1.5 秒内）或在走时再来（连按两下 E、双击）直接返回 true；但发出这条走路之后导航代号（`ctx.nav_gen()`）变过（中途点了地面改道）就不算重复，这一下要重新走过去。已经坐在这张桌上时除了吞掉还说一句「你已经在这一桌了：约人、加入、开始请点按钮。」，并撤销这一下被走开拦截放行的窗口（见 5）。
- `blocks_input()`：见 5。
- `tags(cam, size, out)`：每张有活动的物件一块桌牌 `{i: "c:<oid>", k: "c"}`，世界坐标在 `on_me` 里预先算好（物件锚点上方 1 米，头顶名牌在 2.05 米），逐帧只做投影；离自己超过 15 米不画。文字：等人 `名字 · 等人 n/min`、人够了 `名字 · 可开始 n/max`、进行中 `名字 · n 人`（不放倒计时，免得文字每秒变）。
- 角标：本模块不调 `host.setUnread`（共同活动没有「未读」），不动 `#dockBtn` 角标。页签顺序 `data-order=30`（附近 10、全镇 20、一起 30）。
- 事件处理细节：`interaction` 只处理我这一桌（用 `_mine` 的编号比对，旁观者不弹）；名单与上一次已知名单比较，新增弹「某某 加入了。」、少了且不是我弹「某某 走开了。」；状态由 open 变 running 而我没点「开始」弹「开始了，大约 N 分钟。」（不到一分半钟按秒说，端到端把十分钟缩成约 45 秒）；`cancelled` 弹「这一桌散了：」加服务器原因原文。自己造成的取消不再对自己说一遍：发起人自己走开引起的（取消原因含「太久」，也就是等了太久没凑齐人时仍然说）；原因是「大家都离开了」的（参与者减到零，收到的人必定是最后走开的那一个，包括非发起人）。取消事件里没有「谁造成」的字段，只能按原因判断（`activity_logic.gd` 的 `cancel_text`）。`interaction_done` 只记下 `{interactionId, name, text}` 给「刚才」小卡并立刻清掉走开拦截，不弹提示（main 已弹）。取消和完成时不等 `/me` 就把 `_mine` 清掉，避免玩家在服务器已经结算之后还被拦；并把这个活动编号记进「已结束」表（最近 8 个），之后若有更旧的 `/me`（结算之前读到、结算之后才回来）带着它，`on_me` 当作没有活动，不复活 `_mine`、不擦掉「刚才」小卡。换了场景（`on_scene` 里场景编号变了）立刻清掉旧场景的物件与桌牌，不等新场景的 `/me`。
- `on_enter` / `on_hello` / `on_resync` 里读 `/me` 之前先看 `ctx.playing()`：离开小镇（或被请出、换人）之后 main 可能还有一条刚建立的 WebSocket（`_start_ws_attempt` 的 `ws-ticket` 请求与 `/session` 的回应赛跑，`/session` 先到、进了「已离开」，随后 ticket 才到并照样 `connect_to`），它的 hello 仍会送到这里；这时读 `/me` 打在已经不在场（端到端里还清掉了登录）的会话上，得到 401，main 把它当成登录失效、把页面带回登录页，「进入小镇」按钮忽隐忽现（20.95 的超时）。不在场就什么都不读，在场之后 `on_enter` 再读一次。
- 约人 / 加入 / 开始之后，`_busy` 保持到 `/me` 追上（`state_reached`：约人、加入后我有了活动，开始后活动是进行中；最多等 2.5 秒）：这期间 `actions` 把这类可点按钮换成灰的「稍等…」（id 是 `f:activity:pending:…`，版面不跳），避免回应到了、`/me` 还没回来的空窗里同一个按钮闪回，再点一下得到 busy / already_busy。

## 4. 选座规则

服务器的「走到物件」总是去离出发点最近的使用位，两个人从同一个门进来会叠在一个座位上，服务端不分配座位。所以点桌子时客户端自己挑：在没被别的演员占着（距离小于 0.6 米）的使用位里取离自己最近的，全占了就取最近的，然后用 `navigate` 的地图点形式 `{to: {x, z}}` 走过去。AI 居民走服务器默认路线，可能仍叠座，不处理。

与规格的一处差别：只有茶桌（`kind == tea_table`）有「坐在座位上」的说法。藏书架、灶台、花箱够得着时 `on_pick` 返回 false，走 main 的老路（E 键对空着的物件直接做单人的事、点一下给出动作按钮）；还够不着才替玩家挑一个没人站的使用位。理由：S0 的 25.2 步（E 键对藏书架）要求「没有功能接管、旧行为照常发生」，并且键盘用户靠 E 键一人读书；规格里「已经站在使用位上就吞掉」对茶桌才有意义。

## 5. 走开拦截的状态机

玩家在共同活动里（开始前或开始后）想走开，`blocks_input()` 非空，`main._can_control()`（点地、点物件、点人、地点、回家、E）和方向键每帧都会问它。规则（`activity_logic.gd` 的 `gate`，单测覆盖）：

- 第一次被问：记 `warn_at`、`last_call`，返回提示文字（等人且发起人 / 等人且参与者 / 进行中三种）。
- 第二次尝试放行：必须是「新的一次操作」，且在第一次提示之后 6 秒内。放行后 6 秒的确认窗口里一律放行（一次点地会连问两次：`_on_tap` 与 `_do_navigate`）。
- 「新的一次操作」怎么认（统筹在 40.7 里抓到的缺陷：以前只看「两次被问的间隔大于 300 毫秒」，按住方向键时只要有一帧卡过 300 毫秒——真机上一次卡顿就够——就被当成第二次尝试，不经确认地走开）：
  - 方向键：靠「新的一次按下」这个边沿。`main.key_edge` 是网页层每次新按下加一的计数，`ctx.key_press_edge()` 在方向键按着时返回它、没按着返回 -1，`blocks_input` 把它传给 `gate`。按着不放时每帧都在问、编号不变，哪怕中间卡了 400、800 毫秒也是同一次按住，永远不放行；松开再按编号变了才算第二次。
  - 点击：被拦的每一下点击只问一次（放行之前 `_do_navigate` 不会被调到），每次被问就是一次点击，用时间间隔区分双击。
  - 300 毫秒只剩一个用途：任何两次「新的操作」之间（双击、触摸点两下、松开后立刻连按两下，间隔常在 100 到 250 毫秒）距上一次被问不到 300 毫秒的算同一次手势，不放行。不再用它去区分按住和重按。
- 6 秒：给玩家「看到提示、想一想、再点一次」的时间。过期之后重新提示，免得很久以前的一次提示让以后的误触直接放行。
- 清零：`_mine` 的编号变了或没了（`on_me`）、`interaction_done`、`interaction` 的取消、`on_leave`（含换人）。活动结束后 `blocks_input` 立刻回到空串，玩家不会被卡住。
- 撤销放行（`gate_revoke`）：main 先问拦截、后调 `on_pick`，拦截不知道这次点击的目的。点自己所在的桌子、按 E 都是「不会走开」的点击，却可能被计成放行的第二次；`on_pick` 的「已经坐着」分支在放行后 3 秒（`REVOKE_MS`）内把这次放行撤销（次数退回、窗口作废），免得留下 6 秒窗口、随后手滑点一下地面就无提示地走开并取消整桌。更早的放行（玩家真的确认过要走）不撤销。
- 零行为：没有活动、在小游戏里、这个页面不是控制方（让 main 自己的只读提示去说）时第一行就返回空串，没有分配。「停下手上的事」走 `leave_activity`，不经 `_can_control`，不被拦。

## 6. 与 main 的几处重叠

- E 键：S0 之后 E 先问 `on_pick`。对茶桌：没坐下就走到座位，已经坐下什么都不做（约人、加入、开始用 `#actions` 的按钮）。这意味着 E 键在茶桌上不再直接发起等人的 lobby；给 C7 的「互动」按钮参考：按钮和键盘进的是同一个 `_do_interact`。对藏书架等够得着的物件仍是老行为。
- 「使用中」去重：见 3。
- 活动条（`#activityChip`）：main 原有，不重复。
- 坐下动画：完全是客户端本地规则（`main._update_sitting`：站在茶桌使用位 0.5 米内、且那张桌在 `here.objects` 里 `active != null` 或是我自己的活动）。本段只保证动作之后马上刷新 `/me`、不同的人坐不同的座位。一个路过的人恰好站在活动中那张桌的使用位上也会被画成坐着，这是现有规则，不改。

## 7. 已知缺口

- 报名超时（10 分钟没人来自动取消）和活动自然结束的客户端处理，靠读代码、服务端 `interact.test.ts` 与 40.9 覆盖结束；超时取消的文字路径与「别人造成的取消」同一处，端到端没有专门步骤（要改服务端参数，本段不动）。
- E 键在茶桌上不再直接发起（见 6）。已在活动里按 E 时，第一下仍会被走开拦截拦下并计成第一次尝试（提示「再试一次就走」，而 E 其实不会让人走开）：`blocks_input` 没有「是哪种操作」的参数，只有 main 改了才能区分，本段不改 main；第二下 E 放行后 `on_pick` 说「请点按钮」并撤销放行。
- 进行中用「停下手上的事」退出的人仍站在使用位上，`main._update_sitting` 只看桌子的 `active` 和自己的活动，所以他仍被画成坐着，`#actions` 里只剩灰的「已开始」，也没法重新加入（等人阶段非发起人退出后则是坐着、同时出现「加入」）。要一致得让 `_update_sitting` 排除已退出的人，是 main 的改动，不归本段。
- main 的 `_start_ws_attempt` 在 `/session` 先于 `/ws-ticket` 回应时，会在「已离开」状态下仍连上一条 WebSocket（20.95 的根因之一，见 10.3），本段只在自己的 `/me` 读取上加了在场判断，没有改 main；别的功能在 hello 时若也读网络，会遇到同一个问题。
- 「刚才」小卡只存一张，下一次活动开始或离开小镇时清掉；不存时间（没有「几分钟前」）。
- AI 居民可能仍叠座（走服务器默认路线）。
- 灶台、花箱的专门文案与端到端没有做（通用代码覆盖，没有为它们写步骤）。

## 8. 真机待办（无头浏览器验证不了）

1. 手机真机上点桌子选座、触摸点两下的间隔是否真的小于 300 毫秒。
2. 抽屉里「一起」页签的滚动与裁切（390 宽、360 宽）。
3. 傍晚桌牌的可读性、人多时桌牌与头顶名牌是否叠成一团。
4. 横屏小高度侧栏里的页签。

## 9. 端到端步骤（`40-activity.mjs`）

A 桌面 1440x900、B 手机 390x844 触摸、C 桌面 1000x700（旁观者，也是读书的发起人，名字带 `<i>`）。开服参数把十分钟的喝茶缩成约 45 秒、报名缩成 25 秒（`client-e2e.mjs` 的 `TOWN_PARAMS`），所以每个子步骤都先做最要紧的断言。

| 步骤 | 内容 |
|---|---|
| 40 | 进茶馆、初始：页签在、两张茶桌空着、没有共同活动按钮和桌牌 |
| 40.1 | E 键（连按两下只发一次导航）与点击选座，不坐、出现「约人」；走在路上点地改道后再点同一张桌要重新走过去 |
| 40.2 | 约人：服务器 open、按钮「等人中」、桌牌、坐下、页签倒计时 |

### 10.3 统筹发现的三处失败（`--only=1,20,25,40,60` 在 ccbac5b 上的一遍）和根因

1. **40.7「A 仍应在活动里」**：`gate()` 以前靠「两次被问的间隔大于 300 毫秒」认第二次尝试。按住方向键时每帧问一次，只要有一帧卡过 300 毫秒（那一步最长帧间隔 503 毫秒）就被当成第二次而放行，真机上一次卡顿就会不经确认地走开。改成按「新的一次按下」的边沿认（`ctx.key_press_edge()`，见 5）。单测：`activity_logic_test` 的按住卡顿 400 / 800 毫秒不放行、松开再按放行、连按两下小于 300 毫秒不放行、点击两下小于 300 毫秒不放行；`activity_feature_test` 的真计时用例（按住、中间 450 毫秒、再 450 毫秒，不放行；换新的按下编号才放行）。先看到红（逻辑单测 3 项红；接线单测在把 `key_press_edge()` 的传参去掉后 2 项红），再看到绿。
2. **40.5「再试一次就走」超时**：核实过。报名窗口一共 25 秒，40.2 到 40.4 在这台机器上用了约 26 秒（40.4 结束时写着「报名截止还剩 3.3 秒」），到 40.5 时这一桌已经因「等了太久」散了，没有活动可拦。这是步骤对机器快慢的依赖。40.5 开头改成先保证有一桌够久的（见 9），断言一条没放宽。
3. **20.95 点「进入小镇」超时**：本段造成。在 ccbac5b 上连续跑 `--only=1,20` 失败了两次（统筹那一遍之外又复现一次，第二次带了请求日志）、通过了三次（其中两次带日志）；带日志的失败那次，离开之后请求顺序是 `/session` 的回应先到、`/ws-ticket` 的回应后到，三次通过的都是 ticket 先到，所以这是个看谁先到的竞态。`/session` 先到时 main 进入「已离开」并 `close_now()`，此时还没有连接可关；随后 ticket 到了，`_start_ws_attempt` 照样 `connect_to`，一条 WebSocket 在「已离开」状态下连上并收到 hello。`activity.on_hello` 无条件读 `/me`，而测试此时已清掉登录，得到 401，main 当成登录失效进 `_relogin`，页面进登录流程，`#enterBtn` 被藏起来（Playwright 记录的「可见 → 滚动进视口后又不可见」），点击一直重试到 30 秒。开发分支上没有任何功能在 hello 时读 `/me`，所以那边是过的。改成 `on_enter` / `on_hello` / `on_resync` 里只在 `ctx.playing()` 时才读 `/me`；单测 `t_no_refresh_when_not_playing`（不在场时 hello / resync 读 0 次、在场时各读 1 次），先看到红再绿。main 里「已离开之后仍会连上一条 WebSocket」本身是 main 的问题，本段不改 main，记在 7。
