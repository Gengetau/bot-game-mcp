# 任务书

## 这一段做什么

栖灯镇的三维网页客户端（`client/`）功能已经有了骨架：走路、附近聊天、全镇公屏、共同活动、游戏桌、居民卡。11-14 和 11-15 两次逐张看验收截图，记下了一批「不是坏了，但看着别扭、用着碍事」的地方。这一段把它们收掉。**只动客户端（`client/`、`scripts/e2e/`），不改服务端（`packages/` 一个字不动），不换素材，不动地图。**

美术方向（主人定的，判断「好不好看」时以它为准）：《牧场物语：重聚矿石镇》的生活感加《织梦岛》重制版的微缩场景感；固定斜俯视；米白、木棕、灰蓝屋顶、柔和绿，少量暖橙灯光；目标是「让人愿意在里面闲逛、坐下、聊天」。界面要安静，不抢画面。

动手前先读：`client/README.md`、`client/docs/C1a.md`（面板底座，尤其「S0 之后」一节）、`client/docs/C1b.md`（气泡）、`client/docs/C3.md`（游戏面板的版式与「留给 V1」）、`scripts/e2e/steps/README.md`；代码：`client/town/scripts/rig.gd`（镜头，78 行）、`main.gd` 的 `_process` 里跟随镜头那一段、`_update_tags`、`_on_ui`；`client/town/web/hud.js` 的 `setState`、`setTags`，`hud.css`；`dock.js` 的 `computeLayout`、`freeRect`、软键盘那一段，`dock.css`；`mod/` 下的 `00-chatkit.*`、`nearby.*`、`town.*`、`bubbles.*`、`game.*`；`features/bubble_layout.gd` 和它的单测（纯函数加无头单测的样板）。验收截图在 `client/demo/`（文件名带号段），下面每一项括号里点了当初看出问题的那几张，先用 Read 看图再动手。

下面六项，按影响从大到小排。每一项都写了「现状」「要的行为」「怎么验」。「怎么验」里的数字是验收线，不是建议。

## 一、镜头给面板让位：自己的角色不被抽屉和按钮挡住

**现状**：`rig.follow()` 让镜头的注视点跟着自己的角色，角色永远投影在画布正中。手机上抽屉一开（从底部升起，占掉下半屏），再加上抽屉上方的情境按钮（「认识一下」「约人」）和「停下 / 回家 / 地点 / 聊天」一行，自己的角色只露出头顶（`25-drawer-*`、`20-mobile-chat-drawer`、`62-mobile-home`）。桌面上右侧栏一开，角色仍在整块画布的正中，偏在可见区域的右边，离侧栏很近。

**要的行为**：自己的角色投影在「没被界面盖住的那块画面」的中间偏下一点（建议高度 55% 处；手机抽屉开着时可见区很矮，取正中）。

- 「没被盖住的那块」由网页层算：从整个视口里去掉顶栏、面板（抽屉或侧栏，`dock.js` 的 `freeRect()` 已经有一半）、底部按钮行、`#stack`（状态行与情境按钮）、软键盘。算出来的是一个矩形，归一化到视口宽高之后发给 Godot。**只在版式变化时发**（面板开合、换布局、窗口尺寸变、软键盘起落、情境按钮区的高度变了），不要每帧发，不要每帧读布局；连续变化（拖动窗口）要合并。
- Godot 一侧：`rig` 新增一个「目标屏幕点」（归一化坐标，默认正中）。注视点 = 角色位置 −（目标屏幕点在地面上的落点 − 画面正中在地面上的落点）；这个差只和镜头朝向、距离、宽高比、目标点有关，镜头整体平移不改变它，所以可以直接算。目标点变化时用 0.25 到 0.35 秒缓动过去，不要跳。滚轮和双指缩放照常，缩放时角色仍停在目标点上。
- 可见区太小（高不到 120 像素或宽不到 160 像素，比如横屏手机开着软键盘）时不追：保持上一次的目标点。
- 这不是预测：角色的位置仍然只按服务器给的折线和服务器时间插值，这里动的只是「镜头看哪」。点地面、点人、点物件的命中都走镜头的投影，镜头挪了它们自然跟着对；`_push_debug` 里的 `vp` 矩阵和 `nx / ny` 也要是挪过之后的（端到端全靠它们换算点击位置）。
- 私宅、游戏面板开着时同样适用（游戏面板是浮层，算进被盖住的部分与否由你看效果决定，写进说明）。

**怎么验**（端到端，新步骤）：
- 手机 390x844：抽屉关着时，自己在视口正中附近（横向偏差不超过 8%，纵向落在 45% 到 65% 之间）。依次打开每个页签的抽屉：停稳后（屏障：目标点缓动结束，`__town` 里新增的调试字段说「到位」）自己的投影点落在可见矩形内，四边各留 24 像素以上；自己的名牌的包围盒与 `#dock`、`#bottombar`、`#stack` 都不相交。关上抽屉，1.5 秒内回到正中附近。
- 手机软键盘（用底座的测试钩子 `TownDock.test.setKeyboard`）：键盘起来后自己仍在可见矩形内，或者可见矩形太小、目标点保持不动（两种都要走到）。
- 桌面 1000、1280、1440 宽，侧栏开着：自己的横向位置在可见矩形的 35% 到 65% 之间。
- 版式消息不是每帧发：站着不动 3 秒，Godot 收到的版式消息数为 0（调试计数）；开一次抽屉，消息数不超过 4。
- 缓动期间点地面仍然走到点的那个位置：抽屉刚打开的 300 毫秒内 `clickWorld` 一处，服务器上的导航终点与点的世界坐标相差不超过 `T_POS`。
- 纯函数加无头单测：「目标屏幕点 → 注视点偏移」的换算、缓动、太小不追，放进 `client/tests/`。

## 二、键位提示条：不压按钮，局中不说错话

**现状**：左下角的 `#keyHint`（「WASD 或方向键 移动 · E 互动 …」）约 425 像素宽，贴左；按钮行居中。窗口宽 900 到约 1220 像素时两者相撞，字叠在一起（`25-side-1100-*`）。900 以下整条隐藏。另外，在一局小游戏里（`body[data-game="1"]`）它仍写着「WASD 移动」，这时方向键并不能走。

**要的行为**：
- 任何宽度下提示条都不和按钮行、`#stack`、`#dock`、游戏面板、提示（toast）区相交。放不下时先换成短的（只留按键，不留说明文字），再放不下就隐藏。按实际量到的宽度决定，不要再加一个写死的断点；量宽度只在版式变化时做（可以和第一项共用同一次版式计算）。
- 局中：隐藏，或换成这一局用得上的按键说明（文字放 `shell.html` 的文字库，照 `client:lint` 的规矩，中文不进 JS）。共同活动进行中（走开会被拦）不必改文字。
- 提示条仍然不收指针事件。

**怎么验**：桌面宽 901、1000、1100、1220、1280、1440，侧栏开和关各一遍：`#keyHint` 可见时，它的包围盒与 `#controls`（按钮行）、`#stack`、`#dock` 两两不相交（留 4 像素）；1440 宽且侧栏关着时必须是完整的那一版。进一局数字炸弹（50 号文件的辅助 `scripts/e2e/lib/game.mjs` 有现成的开局办法；或者照 50.05 给面板喂假局面）：提示条里不出现「移动」两个字。

## 三、标签避让：名牌、桌牌、门口牌、物件牌、地点大字不再叠成一团

**现状**：`main._update_tags` 每帧把所有标签的归一化屏幕坐标发给网页，`hud.js` 的 `setTags` 各摆各的，互相不知道对方在哪。结果：自己站在门口时名牌压住「出口」「家门」；手机上地点大字、物件牌、名牌叠在一起；桌牌（功能模块加的 `c` 类）和坐着的人的名牌叠在一起（`40-*`、`50-*`）；地点大字贴到屏幕边被裁掉半个字，在浅色地砖上对比度低。

**要的行为**：
- 摆完位置之后做一遍避让，按优先级从高到低占位：自己的名牌 > 别人的名牌（C6 并入后 NPC 的名牌同级）> 功能牌（桌牌等，`c`）> 选中的物件牌 > 门口牌（`p`）> 其余物件牌（`o`）> 地点大字（`z`）。后占位的如果和已占位的相交：名牌和功能牌往上或往下挪（最多挪一个牌高加 4 像素，挪了还撞就保持原位，名牌永远不隐藏）；门口牌、物件牌、地点大字直接隐藏（淡出），让出位置。
- 不闪：隐藏和重新显示之间要有回差（比如相交超过 2 像素才藏，离开 8 像素以上才重新显示，或者一次决定至少保持 250 毫秒）。两个人并排走的时候名牌不能上下跳。
- 地点大字和门口牌整块落在视口里（左右钳进来，现在只钳了名牌那一类的做法可以沿用）；给它们一个不依赖地面颜色的底（半透明深色小底或描边），在最亮的地砖和傍晚的地面上都看得清。
- 避让写成纯函数（输入：每块牌的类别、中心、宽高、上一次的决定；输出：每块牌的位置与显隐），配单测。放网页层还是 Godot 层由你定：牌的宽高只有网页层量得到（`setTags` 里已经在文字变化时量一次），所以放网页层更顺；网页层目前没有单测跑道，可以加一个 `node --test` 的小目录并挂进 `npm run client:lint`（在说明里写清楚），或者把尺寸回传给 Godot 用现有的无头单测。不要每帧读布局。
- 气泡（`bubbles` 模块，自己有一套 `bubble_layout.gd`）不归这里管，但名牌挪动之后气泡不能压在名牌上：核对一下气泡是按名牌的实际位置还是按固定高度摆的，按需要接上。

**怎么验**：
- 单测：两块名牌重叠时后一块上移且不出屏；名牌压门口牌时门口牌隐藏、名牌不动；回差（在边界上来回 1 像素不翻转）；一屏 40 块牌耗时很小（给一个宽松上限）。
- 端到端：A 站到广场通往住宅区的出口上，A 的名牌与任何可见的门口牌、地点大字不相交。手机上 B 站在茶馆茶桌的座位上、有桌牌时，B 的名牌与桌牌不相交。手机上连续取 10 帧，任意两块可见的牌相交面积不超过各自面积的 5%（名牌之间允许在两个人贴着站时相交，单独说明）。地点大字的包围盒完全在视口内。两个人并排走 5 秒，各自名牌的纵向位置相对于人的投影点的偏移变化次数不超过 2 次。
- 对比度：地点大字、门口牌的文字对它自己的底，按 `scripts/e2e/lib/activity.mjs` 里 `lowContrast` 的算法（可以提出来共用）不低于 4.5:1。

## 四、面板里的小处

1. **聊天列表顶部**：附近聊天和全镇公屏的列表，第一条被固定的标题条压住半行。列表滚到最顶时第一条完整可见（它的上沿不高于标题条的下沿）。
2. **手机上的全镇公屏**（`31-*`、`30-mobile-*`）：聊天区只剩大约四行。390x844、抽屉开着、没有软键盘时，列表的可见高度不小于六行文字；「不指定地点」的选择框换成和面板一致的样式（现在是浏览器默认样式）。别为了腾高度把输入框或发送按钮做小：可点的东西高度不小于 44 像素。
3. **看不清的按钮**：「门牌」和不可用的「停下」是半透明的，在浅色地面上看不清。画面上的按钮（`#controls`、`#actions`、`#stack` 里的）给一个不依赖地面的底：可用时文字对底不低于 4.5:1，不可用时不低于 3:1，而且不可用的仍然一眼看得出是灰的。
4. **气泡折行**：折行后最后一行只剩一个字。用 `text-wrap: pretty` 或 `balance`（Chromium 支持），或者别的办法，让最后一行至少两个字；标点不单独占一行。
5. **只读时提示重复**（`12-*`）：另一台设备握着控制权时，两处提示说的是同一件事。只留一处，或者让两处各说各的（一处说状态，一处说怎么接管）。
6. **页签条**：页签多到要横向滚动时，左边或右边还有内容的那一侧给一个提示（渐隐或小箭头），滚到头就消失。
7. **游戏面板在矮横屏**（C3 留下的）：667x375 且开着侧栏时面板不压提示（toast）区；这个尺寸下「轮到你」的局面不出现内部滚动条。568x320 尽量做，做不到写进说明。

**怎么验**：每一条一个端到端断言（量包围盒、行数、对比度、滚动位置），都放在新步骤里；第 4 条用 `Range.getClientRects()` 数最后一行的字数，喂三段不同长度的文字。第 3 条在正午和傍晚各量一次（`login` 的 `&hour=` 参数）。

## 做事的规矩

- **勤提交**：每做完一项就在自己的工作树里提交一次。反向验证要故意把实现改坏：改坏之前先把手头的改动提交掉，验证完用 `git diff` 确认已经改回原样；改坏的状态绝不能带进提交。
- 机器只有 4 核，浏览器步骤对负载敏感：凡是吃 CPU 的命令（`npm run typecheck`、导出、端到端、无头 Godot）一律包在 `flock /tmp/town-heavy.lock` 里并带超时，排队是正常的，不要绕开锁。
- 新开的工作树里先跑一次 `npm run client:unit`（它会自动导入资源），再跑别的无头 Godot 命令。动了 GDScript 要重新导出（`npm run client:export`，约 2 分钟）；只动网页层用 `npm run client:web` 重建就够。
- 步骤编号用 95 到 98（号段表里 90 到 98 原先都给了 C7；统筹改成 C7 用 90 到 94、V1 用 95 到 98，你在 `scripts/e2e/steps/README.md` 的号段表里照这个改），`meta.id` 全局唯一。新增的通用小工具放 `scripts/e2e/lib/`，不要往 `scripts/client-e2e.mjs` 里加东西。
- 端到端里走到某处一律 `walkTo`；负向断言要有屏障；阈值留余量；手机上的点按用真实点击；刚进镇的人不站在同一个点；`page.route` 之类要 try/finally。每个步骤文件末尾写「怎么让它失败」。
- **旧步骤的断言一个都不许放宽、删除或跳过。** 镜头一挪，旧步骤里凡是假设「自己在画面正中」的地方可能会红：先看它量的是什么。量的是投影或命中的，应该自己就对；真有写死屏幕位置的，改成按投影算，并逐条写进说明（改了哪一步、原来假设什么）。
- 网页层的规矩照旧：中文文字只在 `shell.html` 和各模块的 HTML 里（`client:lint` 会拦）；不用 `innerHTML`；不读写浏览器存储（记住用户的选择这一段也用不着）；样式选择器带自己的前缀，别被 `dock.css` 的重置盖掉。
- 每帧都跑的路径（`_process`、`setTags`）里不许加布局读取、不许加分配大对象的代码；加了什么、每帧多少次，写进说明。
- 汇报里如实写：哪些断言做过反向验证（改坏后确实变红）、哪些只是推演。
- 中途拿不准的事选保守的做法，记进 `client/docs/V1.md` 的「待统筹决定」，汇报时列出。

# 完成的标准

- 六项里一到四每一条「怎么验」都有对应的断言，并且现在是绿的；做不到的逐条写进 notDone 并说明原因，不要悄悄跳过。

# 评审角度

## 评审角度 camera-input：镜头、输入与每帧开销

评审者对照 `rig.gd`、`main.gd` 的跟随与 `_push_debug`、`hud.js`、`dock.js`，找真错误，每条给出具体的操作顺序和错误结果。逐项查：1) 镜头挪了之后，点地面、点人、点物件、E 键选最近、手机点按、双指缩放、滚轮缩放的命中是否都还对（尤其缓动进行中、目标点刚变的那几帧）；`_push_debug` 的 `vp`、`nx / ny` 与真实画面是否一致。2) 版式消息：哪些变化会触发、有没有漏掉的（横竖屏切换、地址栏伸缩、软键盘、情境按钮区高度变化、页签切换导致抽屉高度变化、游戏面板开合、进入「已离开」面板）；有没有可能每帧发或者互相触发成环；消息在 Godot 还没准备好时到达会怎样；重新登录后目标点有没有复位。3) 可见区太小时是否真的不追，从「太小」恢复时会不会跳。4) 每帧路径上新增了什么：有没有布局读取、DOM 查询、字符串拼接、数组分配；`setTags` 的避让在 40 块牌时的耗时。5) 「不做预测」有没有被破坏：角色位置是否仍只来自服务器折线。6) 对 `main.gd` 的改动是否限制在任务书允许的几处。

## 评审角度 layout-visual：版式与观感

评审者**逐张用 Read 看截图**（实现者留的和自己重新出的），并读 CSS，找仍然存在或新引入的版式问题，每条给出尺寸、状态和看到的现象。逐项查：1) 六项里每一条在任务书列的每个尺寸下是否真的解决；任务书没列的常见尺寸（360x640、412x915、768x1024 竖横、1366x768、1920x1080）有没有明显问题。2) 标签避让的观感：名牌挪动是否突兀、门口牌是不是在该看见的时候被藏了（站在门口最需要看到门口牌，它却被自己的名牌挤掉，这种情形怎么处理的）、地点大字的底是否抢画面。3) 颜色和对比度是否守住定下的色板，新加的底、描边、渐隐是否和现有界面一致；不可用的按钮是否仍然一眼看得出不可用。4) 有没有为了过断言而做的怪事（把东西挪出屏幕、把字缩小到 11 像素以下、把可点区域缩到 44 像素以下）。5) 中文文字是否都在 HTML 文字库里，新文字读起来是否自然。6) 「看到但没做」的清单是否如实。

## 评审角度 e2e-quality：端到端与测试质量

评审者找不可靠的测试和没有被守住的行为，每条给出具体的改坏办法和「改坏后哪一步该红却不红」。逐项查：1) 每一条「怎么验」是否真的有断言、是否能抓到对应的回归：照汇报里的反向验证清单抽查至少三条自己重做（包含镜头让位那一条），其余按代码推演，实测与推演分开写。2) 负向断言的屏障够不够（「没有相交」「没有消息」之前是否等到了该等的东西）。3) 有没有写死秒数的等待、依赖机器快慢的地方；量包围盒时元素是否已经稳定（缓动结束、字体就绪）。4) 旧断言有没有被放宽、删除、跳过；被改的旧步骤是否确实是写死了屏幕位置，改法是否等价。5) 单测是否覆盖边界（目标点在角上、宽高比极端、牌贴边、牌比屏幕宽）。6) 完整的一遍端到端是否真的跑过（要有日志里的步骤数和耗时），有没有未声明的 4xx、控制台错误。
