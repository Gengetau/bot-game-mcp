# 任务书

## 0. 背景与范围

栖灯镇的 Godot 网页客户端（`client/`）到现在能走路、聊天、共同活动、玩一局小游戏、看居民卡、和 NPC 说话买东西。设计文档（P1）还要求「手机操作方式和连接异常反馈」，客户端体验验收表里有一条「状态反馈：失败、等待、只读和断线有明确提示」，第一条试玩里有「一名真人退出……再次进入恢复身份、物品和合法位置」。现在的缺口是三件：

1. 手机上没有 E 键，要互动只能去点很小的人和物件。
2. 连接出问题时只有左上角一个小圆点和「重连中… / 离线」三个字，分不清是自己断网、服务器连不上、登录过期，还是在别处离开了。
3. 界面上没有「离开小镇」的入口（现在只有接口 `POST /town/api/leave`，端到端里是代发的）。

这一段把这三件补上，再加一张首次进入的提示卡和两件小事（第 4、5 节），只改客户端和端到端：`packages/` 一个字不动，不改 `docs/TOWN.md`。服务端有缺口就写进汇报的「待统筹决定」，不要自己改。

第一条试玩的整条端到端是下一段（C7b）的事，本段不做；但本段的三件东西 C7b 会直接用，所以调试口要留好（见各节「调试口」）。

## 1. 手机「互动」按钮

### 现状

- 桌面按 E：`main._do_interact(src)`。它用 `_nearest_pick(自己)` 选出 `INTERACT_RANGE`（8 米）之内离自己最近的物件或别的角色（居民和 NPC 都在 `actors` 里），先问 `_can_control(kind, id)`（功能模块的拦截，比如共同活动里「走开就退出」的确认），再问 `features.on_pick(kind, id, src)`，没有功能接管才走老路（靠近那个人、走到物件旁、够得着就做物件的动作）。
- `src` 有三种：`tap`、`key`、`button`。功能模块不许按来源分支。`button` 这一种现在还没有入口，本段补上。
- 网页层用 `hasKeyboard`（`(hover: hover) and (pointer: fine)`）决定显不显示键位提示条 `#keyHint`。

### 要做的

1. Godot 这边：把「现在按 E 会选中什么」算出来推给网页。在 `_push_state` 的状态里加一个字段（建议 `interact`）：没有目标时是 `null`；有目标时是 `{kind, id, label}`，`label` 是给人看的名字（物件的名字、居民的名字、NPC 的名字）。选中的算法只有一份，就是 `_nearest_pick`，不要另写一套。它每帧都会变，所以只在「选中的东西换了」时标脏（`_dirty`），不要每帧推状态。
2. 网页这边：`shell.html` 里加一个按钮（建议 `#interactBtn`），文字「互动」加目标名字（名字过长时省略，按钮不变宽到挤掉别的）。只在下面条件都成立时显示：没有键盘（`!hasKeyboard`）、阶段是 `playing`、`interact` 不是 `null`。有键盘的设备不显示（它们有 E 键和提示条）。
3. 点它：`emit('ui', 'interact', '')` 之类（事件名你定，和现有风格一致），Godot 收到后调 `_do_interact("button")`。**结果必须和按 E 完全一样**：同一个选中、同一次拦截询问、同一个功能接管。不要在按钮这条路上另加判断。
4. 只读（控制权不在这台设备）、登录中、已离开、小游戏面板盖着的时候：按钮不显示，或者显示但点了和 E 一样被拦并给同一句提示。两种里选一种，全段一致，并在说明里写清楚。建议：`mine` 为假时不显示（只读横幅已经在说了）；其余状态照 E 的行为。
5. 连点两下只生效一次：按钮这条路和 E 一样可能在 `on_pick` 之前等一小会儿（等 `/me`），各功能模块自己有防重入；你要保证的是按钮本身在「上一次还没处理完」时不重复发（Godot 侧一个忙标记，和 E 共用更好），并用端到端测一次。
6. 版式：按钮在手机竖屏 390×844 和横屏 844×390 都点得到（真实点击命中它，不被别的元素盖住），最小 44×44 CSS 像素；不压住 `#controls` 里的四个按钮、`#actions` 里的动作按钮、提示条、只读横幅；抽屉（`#dock`）打开时不被抽屉盖住也不盖住抽屉的把手和页签（放到抽屉上方，或者抽屉开着时不显示，选一种并写明）；小游戏面板开着时不显示。安全区（`env(safe-area-inset-*)`）要留。
7. 无障碍：`aria-label` 写全（「和 某某 互动」），目标变了 label 跟着变；不要抢焦点。
8. 文字全部写在 HTML 里（现有规矩：`web/` 下的 JS 里不放汉字，用 `data-*` 文字库或模板）。

### 调试口

`window.__town.interact`（或放进现有的 debug 推送里）：当前选中的 `{kind, id, label}` 或 `null`。C7b 要用它等「按钮指着茶桌了」。

## 2. 连接异常的分类提示

### 现状（开工先自己读代码核对，把核对结果写成一张表放进说明文档）

- `_conn_state()` 只有三个值：`ok`（WebSocket 收到 hello）、`reconnecting`（想连但没连上）、`offline`（不想连）。网页把它显示成圆点颜色加「重连中… / 离线」。
- 断线后的行为已经有了，而且有测试（旧步骤 10、13、14，20.95 到 20.97）：退避重连（1 秒起、翻倍到 15 秒、带抖动）、死连接检测、4403 之后先查 `/session` 再决定（登录没了去重新登录、人不在场了进「已离开」、都还在就重连）、401 走重新登录、断线期间导航续租退回 HTTP。**这些行为一个都不要改**，本段只加「告诉用户现在是哪一种」。
- 只读（控制权在别处）已经有横幅 `#readonly` 和「接管」按钮，不动。

### 要做的

1. 把「现在是哪一种异常」归成下面几类（一个纯函数，放在不依赖场景树的新文件里，例如 `client/town/scripts/conn_logic.gd`，输入是几个简单的量，输出是类别；配无头单元测试）：

   | 类别 | 什么时候 | 给用户看什么 |
   |---|---|---|
   | 正常 | WebSocket 已连上 | 不显示横幅 |
   | 短暂重连 | 断开不到 3 秒 | 只有现有的圆点和「重连中…」，不显示横幅（避免闪一下） |
   | 重连中 | 断开超过 3 秒，浏览器认为有网 | 横幅：连接断开了，正在重新连接；画面可能不是最新的，连上以后自动恢复。带一个「立即重试」按钮 |
   | 没有网络 | 浏览器报告离线（`navigator.onLine === false` 或 `offline` 事件） | 横幅：设备没有网络；连上网以后会自动重连。不带按钮 |
   | 服务器连不上 | 浏览器有网，但连续几次（建议 3 次）重连都失败，或者 HTTP 请求连续拿到 5xx / 连接失败 | 横幅：小镇暂时连不上，可能在维护；会一直重试。带「立即重试」 |
   | 登录过期 | 401 触发了重新登录 | 登录面板上多一句「登录过期了，请重新进入」（现在是直接切到登录面板，没有解释） |
   | 已离开 | 进入了「已离开」面板 | 面板文字区分两种：自己在这台设备上点了离开（「你已经离开了小镇」）；不是在这里点的（在别处离开，或被服务器请出）（「这位居民已经在别处离开了小镇」）。两种下面都是「进入小镇」按钮，都不自动重新进入 |

   阈值（3 秒、3 次）写成常量，单元测试里按边界测。类别只由这个函数决定，网页层只管按类别显示，不自己推断。
2. 「立即重试」：把退避清零、马上发起一次重连（现有的 `_drop_dead_ws` / `reconnect_at = 0` 这条路，看代码选对的那个）。连点不叠加（已经在连就不再发起）。它不绕开 `revoke_checking` 和会话代号的规矩（见 `C2b.md`）：正在查 `/session` 时点它不起作用。
3. 横幅放在现有的 `#stack` 里（和只读横幅同一个地方、同一种样式），和只读横幅同时出现时两条都显示，不互相盖。横幅出现和消失不移动镜头、不打断走动中的画面。
4. 断线期间用户的操作：现在点地、发话各自有失败提示。核对一遍这些提示在「没有网络」「服务器连不上」时说的是人话（不是 `net_fail` 这类内部词），不合适的改掉；但不要预先禁用按钮（恢复的那一刻用户不该还要等界面解禁）。
5. 网页从后台回到前台（`visibilitychange`）：核对现在的行为（死连接检测会不会马上触发重连）。如果回来以后要等到下一次探测才发现断了，就在回到前台时主动探一次。只在确认有这个问题时改，并写明前后对比。
6. 文字全部在 HTML 里。横幅用 `role="status"`，不要用会打断读屏的 `alert`。

### 调试口

`window.__town.connKind`（类别的英文键，例如 `ok` / `brief` / `reconnecting` / `no_network` / `unreachable`）和「已离开」的原因键。C7b 和本段的端到端都靠它等状态，不要去读横幅的文字。

## 3. 「离开小镇」入口

### 现状

- 服务器：`POST /town/api/leave`（`identity.ts` 的 `leaveWorld`）立刻取消在场；之后旧心跳不能把人悄悄恢复为在场。客户端收到 4403 或心跳的 `presence_lost` 后查 `/session`，发现人不在场就进 `_enter_left_state()`：换会话代号、不再连网、清掉角色、停在「已离开」面板，等用户点「进入小镇」。旧步骤 14 测的是「接口代发离开之后页面停在已离开面板、不自动重新进入」。
- 界面上没有任何地方能离开。

### 要做的

1. 入口：顶栏（`#topbar`）里加一个「离开」。手机顶栏已经很挤（地点、画质、声音、音量、旧页面），所以做法由你定，但要满足：390 像素宽时顶栏不换行、不溢出、每个可点的东西都点得到。可以把「画质 / 声音 / 音量 / 旧页面 / 离开小镇」收进一个「菜单」按钮；也可以只把「旧页面」和「离开小镇」收进去。V1 之后顶栏的版式以开工时的实际情况为准，开工先看一眼。
2. 点「离开小镇」先确认（一个小对话框，不用浏览器的 `confirm()`）：说明「离开后你的角色会从镇上消失；身份、硬币和物品都会保留，随时可以再进来」。如果此刻手上有共同活动或在一局小游戏里，多说一句「正在进行的活动 / 对局会按规则处理（等于中途离开）」，文字按 `my_interaction` 和 `ctx.in_game()` 的实际状态选。两个按钮：「离开」「再待一会儿」。Esc 和点对话框外等于「再待一会儿」。
3. 确认后：`POST /leave`（带 `clientId`）。成功就直接进 `_enter_left_state()`（不要等 WebSocket 的 4403 绕一圈），原因记成「自己在这里点的」；失败（网络不通、5xx）时不进已离开状态，提示一句「没能离开，稍后再试」，人还在镇上。请求在路上时按钮禁用，回来以后对会话代号（期间如果已经换了会话，这份结果丢掉）。
4. 只读状态（控制权在别处）也可以离开：离开的是这位居民，不是这台设备。确认框里多说一句「另一台设备上的画面也会一起退出」。
5. 离开之后：现有的「已离开」面板，不自动重新进入；各功能模块的 `on_leave` 照常被调到（清空自己的东西）；声音怎么处理看现状（现在离开后音乐是否还在响），不合理就让它淡出，合理就不动，写明。
6. 再进入：点「进入小镇」回到镇上，是同一位居民（编号不变）、位置合法、硬币和物品没变。这条现有流程已经能做到，本段用端到端钉住。
7. 文字全部在 HTML 里。对话框可用键盘操作（Tab 能走到两个按钮，Enter 确认当前按钮），打开时焦点进对话框，关掉后还给原来的按钮。

### 调试口

`window.__town.leaveBusy`（离开请求是否在路上）；对话框用稳定的 id（`#leaveDialog`、`#leaveConfirmBtn`、`#leaveCancelBtn`）。

## 4. 首次进入的一次性提示

### 现状

新玩家最容易卡住的几处（11-13 排查时记下的）：不知道怎么开口说话（聊天面板默认关着，手机上没有键位提示条）；不知道桌子、书架、人可以点；附近和全镇两个输入框分不清。桌面有键位提示条 `#keyHint`，手机什么都没有。

### 要做的

1. 这台设备第一次进到镇上（阶段第一次变成 `playing`）时，出一张小提示卡，三行以内，按设备说不同的话：
   - 有键盘：点地面或按 W A S D 走路；走近人或物件按 E 互动；按 Enter 说话，附近的人听得到。
   - 没有键盘：点地面走路；走近以后点「互动」，也可以直接点人和物件；点「聊天」说话，附近的人听得到。
   卡上有一个「知道了」按钮。
2. 只出一次：点了「知道了」之后在这台设备上记一个标记（`localStorage`，键名用现有的 `town3d.` 前缀，读写走 `hud.js` 里现成的带 try/catch 的那两个函数；只存一个布尔标记，不存任何和居民有关的东西）。同一台设备换人登录、刷新、重新进入都不再出。存储不可用时每次进入都出，但仍然能关。
3. 它不挡操作：卡片本身不收指针事件，只有「知道了」收；位置不压住底栏按钮、互动按钮、只读横幅、连接横幅、抽屉。小游戏面板开着、登录面板或「已离开」面板显示着的时候不出。出现和消失不移动镜头。
4. 端到端里别的页面默认不该出这张卡（它会改变几十个旧步骤看到的画面）。办法：在 `scripts/client-e2e.mjs` 建页面的公共函数里默认预先写上「看过了」的标记，测这张卡的步骤用一个不带标记的新页面。**这是本段唯一允许改 `client-e2e.mjs` 的地方**，改动限于这一处（加一个参数和一行 `addInitScript`），并在汇报里贴出改动。
5. 文字全部在 HTML 里；`role="note"`，不抢焦点。

**91 号：连接异常**

- 91.1 A 的 WebSocket 被掐断并挡住重连（照旧步骤 10、13 的做法）：3 秒内调试口是 `brief`、横幅不出现；超过 3 秒变成 `reconnecting`、横幅出现。放行后回到 `ok`、横幅消失，A 的位置和服务器一致。
- 91.2 「立即重试」：挡住时点它，立刻多一次连接尝试（数 WebSocket 构造次数）；放行后再点，马上连上，不用等退避。正在查 `/session` 时点它不起作用。
- 91.3 没有网络：`context.setOffline(true)`，调试口 `no_network`、横幅是那一句且没有按钮；恢复后自动连上。
- 91.4 服务器连不上：挡住 WebSocket 并让 HTTP 返回 503，连续失败够次数后调试口 `unreachable`；恢复后回到 `ok`。注意全程检查会把 5xx 记成问题，要用 `allowFailure` 声明。
- 91.5 登录过期：清掉 Cookie 后触发一次 401（照 20.97 的换人做法里清 Cookie 那一步），登录面板出现并带「登录过期」那一句。
- 91.6 在别处离开：接口代发 `/leave`，页面进「已离开」，原因是「不是在这里点的」那一句。

**92 号：离开小镇**

- 92.1 A（桌面）点入口 → 对话框 → 「再待一会儿」：没有 `/leave` 请求（屏障：之后发一句话并收到回执），人还在。
- 92.2 A 点入口 → 「离开」：发了一次 `/leave`；A 进「已离开」（原因是「自己在这里点的」）；B 的页面里 A 消失；服务器的公开投影里 A 不在场；之后 30 个调试推送内 A 没有新建 WebSocket（照 20.96 的做法）。
- 92.3 A 点「进入小镇」：同一个居民编号；位置合法（在可走区域内、不在别人身上）；`/me` 里的硬币和背包和离开前一样。
- 92.4 B（手机）走一遍 92.1 和 92.2 的界面部分（入口点得到、对话框不超出屏幕、按钮够大）。
- 92.5 共同活动进行中点离开：对话框里有「正在进行的活动」那一句；确认后活动里另一位看到的是「有人中途离开」的正常处理（不卡住）。
- 92.6 `/leave` 失败（让它返回 503）：提示一句，人还在镇上，调试口 `leaveBusy` 回到假，再点可以重试。
- 92.7 离开请求在路上时换了会话（扣住 `/leave`，期间接口代发离开并重新进入，再放回）：迟到的结果不把新会话带进「已离开」。扣住的请求要在页面自己的 15 秒超时之前答复，放在 try/finally 里。

# 评审角度

## 评审角度 lifecycle：会话、离开与重连的正确性

对着 `main.gd` 的会话代号、`revoke_checking`、`_enter_left_state`、`_relogin`、`_schedule_reconnect` 找真问题，每条给出「操作步骤 → 错误结果」：1) 离开请求在路上时发生重新登录、被别处接管、WebSocket 4403、再次点击，各会怎样；迟到的 `/leave` 结果会不会把新会话带进「已离开」。2) 「立即重试」在 `revoke_checking`、正在登录、已离开、只读时点会怎样；会不会绕开退避造成连接风暴（按住不放、连点）；会不会在「已离开」状态下连上 WebSocket（20.96 守的那件事）。3) 类别函数的输入有没有可能自相矛盾（例如浏览器说离线但 WebSocket 还开着），优先级是否合理；阈值边界有没有抖动（横幅一闪一闪）。4) 「已离开」的两种原因会不会判反（自己点的显示成别处离开，或反过来），重新进入之后原因有没有清掉。5) 离开之后各功能模块的 `on_leave` 是否都被调到，有没有东西留在页面上（聊天列表、居民卡、NPC 菜单、小游戏面板、信箱）。

## 评审角度 mobile-layout：手机版式与可达性

390×844、844×390、360×640、1440×900 四种尺寸下：1) 互动按钮、顶栏的新入口、横幅、确认框有没有互相盖住或盖住已有的控件（`#controls`、`#actions`、`#keyHint`、`#readonly`、抽屉把手和页签、提示条、名牌）；真实点击命中的是不是它自己。2) 抽屉开着、小游戏面板开着、键盘弹出时这些东西在哪。3) 触摸目标是否不小于 44×44，安全区是否留了。4) 文字是否都在 HTML 里；`aria-label`、`role`、焦点管理是否合理（确认框的焦点陷阱、Esc）。5) 互动按钮的目标名字过长、目标频繁切换（两个人在 8 米内来回走）时按钮会不会跳动、变宽、闪烁。

## 评审角度 e2e-quality：端到端的质量

逐步看 `90-controls.mjs`：1) 每条断言会不会在实现坏掉时仍然通过（重点看只读页面里会被别的东西改回来的状态、只看文字不看调试口的断言、没有屏障的负向断言）；挑两三条按「怎么让它失败」实测。2) 有没有写死的等待、过紧的阈值、对随机串的短串断言、对两位新居民站位的假设。3) 扣住请求的地方是否都在 15 秒内答复、是否都有 try/finally、是否声明了预期的失败（`allowFailure`）。4) 步骤之间有没有残留状态（离线没恢复、Cookie 被清、路由没撤）会让后面的步骤连带失败。5) 这个文件单跑、和 20、25 号一起跑、放在完整一遍的最后跑，是否都稳。
