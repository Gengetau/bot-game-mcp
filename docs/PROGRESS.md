### 长期约定（主人定的，后面一直适用）

- **合并**：PR 的 CI 绿了、自己的评审也过了，就自己合并，不用再问。**部署到服务器仍然每次先问。**
- **美术方向**：《牧场物语：重聚矿石镇》的生活感 + 《织梦岛》重制版的微缩场景感。约三头身；木结构、瓦顶、暖帘；米白、木棕、灰蓝屋顶、柔和绿，少量暖橙灯光；材质简洁柔和；固定斜俯视；白天要好看，傍晚点灯是特色。保持三维，不做 HD-2D。目标是「让人愿意在里面闲逛、坐下、聊天」。

- **做了什么**：桌面上按住 WASD 或方向键，角色朝对应的屏幕方向走，松开约 0.3 秒内停下；点地照旧，手机不变。服务器权威：客户端只发方向、序号和控制版本，不发坐标。
- **协议**：WebSocket 消息 `{t:"dir", seq, epoch, x, z}`（`x`、`z` 是方向向量，幅度超过 4 拒绝，零向量 = 停）。客户端按住时每 175 毫秒重发，换方向最快 60 毫秒一次。服务器回 `dir_dropped`（stale / rate_limited）或 `error`（`control_lost`、`not_present`、`in_activity`、`bad_request`）；hello 里带 `dirLeaseMs`。
- **服务端做法**（`space.ts` 的 `directionInput`）：
  - 每条输入都从 `posOf` 重新算一段短直线：长度上限 = 速度 2.4 米每秒 × `dirLeaseMs`（500 毫秒）= 1.2 米，租约截止 = 现在 + 500 毫秒，走现成的租约截断。
  - `spatial/sweep.ts` 的 `sweepDirection`（纯函数）沿方向找最远可走点；撞了就沿单轴贴墙滑动。
  - 导航类别 `target.kind='dir'`；`nav_revision` 照常递增，`nav_step` 任务照常校验编号和版本。
  - 不发任何事件：到期停步不发 `nav_stopped`，走完不发 `you_arrived`；回执里没有坐标；`renewNavigation` 对 `dir` 导航返回 `ok:false`。
  - 排序比较（连接序号，seq），新连接盖旧连接；epoch 不对或不是控制者 = `control_lost`。每居民内存令牌桶：突发 10，每秒 10 条。
  - 零向量只停 `dir` 导航，不会取消点地的长路线。点地和方向输入谁后到谁接手。

**P0 服务端的设计决定**

- 位置只有一个写入方：空间模块（`packages/engine/src/world/spatial/`）。权威位置是「场景 + 实例 + x + z」，存在 `world_actors` 表；走路时不存每帧坐标，用 `positionAt(运动, 时刻)` 现算。
- 旧 `location_id` 降级为区域标签，由空间模块在跨区域的那一刻改写（同一事务里触发原来的离开 / 到达钩子和事件）。`move_json` 不再使用。旧的 `move {to}` 是 `navigate` 的别名。
- 地图是一份数据（`MapSource`，带 `mapVersion` 和校验值），服务器栅格化成网格；客户端拿编译后的清单画灰盒，不自己栅格化。后端不依赖 Godot。
- 一张公共场景 `town`（六个公共地点 + 路 + 住宅接入点都在同一张网格里，室内靠墙和门洞），一张私宅场景 `home`（每户一个实例，实例号 = 房主）。两条住宅巷合并成一个公共住宅接入点 `residential`；`street_id` / `house_no` 只剩门牌的意思。
- 导航：`navigate`（目标可以是地点别名、物件、居民、地图点）和 `stop_navigation`；每次变化 `navigationRevision` 加一，定时任务 `nav_step` 必须对上导航编号和版本才生效。导航租约 10 秒、每 3 秒续一次（不走回执管线）；`positionAt` 截断在租约截止时刻。离线、被接管、控制连接断开都立即停步。重启后停在最后一个耐久检查点。
- 走路时可以说话、可以做现场动作（按所在区域）。P0 里人与人的互动仍按「同一区域」，公共物件按距离（够不着返回 `too_far`，先 `navigate` 到物件）。按距离听见说话、公屏、NPC 是 P1。
- 实时通道：WebSocket `/town/ws`（一次性连接票据），发空间快照和增量，也转发耐久事件；导航变更等耐久动作仍走 HTTP。SSE 保留给旧客户端。

## 2026-11-10：bot 不能再替人报名

## 2026-11-09：真人座位网页链接

- 主人的需求：真人像剧本杀的观战链接一样点链接加入，结束后作废。做法是给每个真人一个座位令牌。
- 引擎：
  - 开局时（配置了 `webUrl`）给每个真人座位生成随机令牌（`rec.seatTokens`），通过 `tell` 私聊发链接 `webUrl?g=局号&s=令牌`。这条消息算身份类，问「我身份呢」会一起补发。
  - 对局结束或中止时，`touch` 里删掉令牌，链接立即作废。
  - 没配 `webUrl` 就不发链接，真人照旧私聊裁判玩。
- 接口：
  - `GET /web/api/games/:id/seat?s=`：本座位视图，内容是公开部分（和观战同口径）加上自己的私密视图、待办、发给自己的私密消息。不含观众席，参与者看不到观众席。
  - `GET …/seat/stream?s=`：SSE 推送。
  - `POST …/seat/act?s=`：`{text, mode: command|speech}`，只收 JSON。
  - 指令和私聊裁判走同一套解析（`humanInput`，从 `relayHumanMessage` 抽出来的）。页面上提交的结果直接显示，不再私聊发「✅」。
  - 观战令牌和座位令牌互不通用。
- 网页舞台的变化：
  - 配了 `webUrl` 就收真人报名。
  - 真人在座位网页上发言，由裁判加「【N号 名字】」前缀镜像到群里。
  - 真人在群里说的话不算数，引擎忽略。代码裁判会撤回，并私聊提醒他去座位网页发言（不说 speak）。
  - `referee_step` 新增 `human_ids`。

## 2026-11-06：狼人杀加入自爆和狼王

6~7 人局用屠城之后，狼 0 胜 3 负，所以给狼加两样正式规则里就有的能力。

**自爆**（选项 `self_explode`，默认开启）
- 白天这些阶段可以自爆：警长竞选报名、竞选发言、警长定序、起跳、发言、PK 发言。
- 存活的狼人（含狼王）在群里发「自爆」，AI 调用 `act({"action":"explode"})`。
- 自爆者亮明身份立即出局，没有遗言。当天剩下的发言和投票全部取消，直接进入黑夜。
- 警长竞选中自爆，警徽流失，本局不再竞选；自爆的人是警长，警徽也随之流失。
- 遗言、开枪、移交警徽和投票时不能自爆。

## 2026-11-05：临时会话要对方先开口；补发没送达的私聊
