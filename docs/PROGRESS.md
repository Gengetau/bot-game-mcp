# 开发进度与测试记录

## 2026-11-06：bot 自己开的房（WW-NXSM）

外接 bot「休」直接调用 create_game 开了狼人杀房间，结果房间开不了局，最后被中止。原因有两个：

1. **真人「加入」登记失败。** 参赛模式下妮娅不会报名别人开的房间，而引擎只允许已报名的 AI 代为登记真人。
   - 修复：裁判发现别人开的房间后，妮娅自动报名「都行」。不是参赛模式时，报名「裁判」。
   - 另外，开房后裁判最多要 5 秒才能刷新到这个房间，这期间真人发的「加入」会被丢掉。现在收到群消息时如果还没有对局，先刷新一次。
2. **无法自动开局。** 只有房主能开局，妮娅不是房主。
   - 修复：服务器配置了 `refereeIds` 时，名单里已报名的账号也可以开局。

测试：引擎和裁判共 236 个全部通过。裁判测试新增一项：bot 开房后马上「加入」，能登记、能自动开局。

## 2026-11-05：复盘 WW-NYZY 后的修补

- **女巫在解药用掉后能否看到刀口**：新增狼人杀选项 `witch_sees_victim`：
  - `until_antidote`（默认，主流规则）：解药用掉后不再告知；
  - `always`：始终告知（小屋服务器用这个）。
- **真人发言末尾带「过」直接结束发言**：例如「我觉得 3 号是狼 过」，记录「我觉得 3 号是狼」，并结束本轮发言。识别的结束词有 过、我过、说完了、发言完毕、完毕、pass、over 等。
- **发言里的 QQ @**：@ 本局玩家变成「@昵称」；@ 局外人直接去掉。以前会变成乱码「［CQ:at…]」。
- **刺猬被跳过发言**：bot 自己发群消息（selfPost）时，它的群消息可能晚于下一位的发言提示到达。现在引擎在下一条群消息上加 `wait_for_post`；代码裁判会等这个 bot 的消息出现在群里（最多 `postWaitMs`，默认 60 秒）再发下一条。
- **警长定发言顺序，起跳环节默认关闭**（按主流规则）：
  - 有警长时，每天讨论前警长发「顺序」（号码从小到大）或「逆序」（从大到小），超时按顺序（`sheriff_order_timeout_s`，默认 30 秒）。
  - 昨夜单死时从死者的下一位开始，否则从警长的下一位开始，警长最后发言归票。
  - 没有警长时：单死从死者下一位开始，方向随机；否则随机起点、随机方向。
  - `claim_phase` 默认改为 false；打开时也只在没有警长的日子生效。
- **夜间禁言**（代码裁判，默认开，`--no-night-mute` 关闭）：
  - 引擎在 referee_step 结果里给出 `quiet_ids`，内容是秘密阶段（狼人杀的夜晚、女巫阶段）存活的 AI 玩家。
  - 这些玩家在群里说话时，裁判撤回消息，禁言到天亮，并在群里提醒一次；天亮或对局结束时解除禁言。
  - 夜晚开始后 15 秒内不管（`quietGraceMs`），给 bot 回完白天最后一句话留出时间。
  - 真人和出局的玩家不管。
  - QQ 不允许管理员禁言另一位管理员，禁言失败时只撤回并提醒。
- **妮娅（主账号）能上场了**：`--main-plays` 模式下，裁判进程开房时，主账号的报名从「裁判」改成「都行」。抽签抽中它就当裁判；抽中别人，它就上场当玩家；抽不出别人时，仍由它坐庄。
- **剧本杀 DM 不会被抽去当裁判**：新增游戏定义钩子 `mustPlay`，剧本杀返回 `host`。指定的 DM 不进裁判抽签；即使它以裁判候选的身份报名，也会入座当 DM。小屋服务器把 `"host":"3127771953"`（克蕾雅）放进裁判的默认选项，这个选项只有剧本杀会用到。
- **云盘素材库适配实际的文件夹结构**：
  - 剧本文件夹可以带标题，比如「045-夜总会杀人夜（6人封闭）」；
  - 图片路径可以带子文件夹，比如 `线索/04.jpg`。
  - 小屋的服务账号是 jubensha-reader，根文件夹下现有 045、371、同学会、804 四个剧本。其中「同学会」没有 id 前缀，需要改名。

## 2026-11-05：狼人杀发言流程与观赏性

- **起因**：前几局 6 人局里狼人全胜（屠边），第 1 天大家都说「等预言家」，预言家和女巫排在后面发言时前面毫无信息；结束时也看不到夜里发生了什么。
- **起跳环节**（`claim_phase`，默认开）：每天讨论前限时 30 秒，发「起跳」的人按起跳先后最先发言，其余人随后。当天有警长竞选时跳过。
- **两轮发言**（`second_round`，默认关）：全员发言一轮后，再按同样顺序补充发言一轮，然后投票。
- **警长竞选**（`sheriff`，默认 auto＝8 人及以上）：
  - 第 1 天报名「上警」，上警者竞选发言，其余人投票。
  - 平票则 PK 一次，仍平票则警徽流失。只有一人上警时直接当选。
  - 警长放逐投票算 1.5 票，最后发言归票，发言从警长下一位开始。
  - 警长出局时在遗言后移交警徽或撕警徽，超时视为撕。
- **胜负规则**：`win_mode` 新增 `auto` 并设为默认，6~7 人屠城，8 人及以上屠边。实际规则存在 `state.winMode`，旧存档按原来的选项处理。
- **夜间复盘**：每晚的刀、守、救、毒和查验记在 `state.nightLog`，结束时随结算一起公布。
- **AI 提示**：加了几条玩家提示：不要只说「等预言家」；预言家第 1 天起跳报验；女巫可报银水；警长要归票。
- **测试**：老测试固定成「无起跳、无警长、屠边」的经典流程，另新增 7 个用例。`npm test` 198 项全部通过，e2e 通过，`npm run docs` 已重新生成。

## 2026-11-05：临时会话要对方先开口；补发没送达的私聊

- **现象**：WW-TFMF 里，真人 837945659 不是裁判妮娅的好友，没有收到身份牌。他私聊问「我身份呢」之后，后面的私聊（狼队友的密谈）就能收到了。
- **原因**：NapCat 只能回复已经存在的临时会话。对方没先私聊过时，带 `group_id` 发送会报 `no such temp session`。
- **修补**：好友私聊和临时会话都失败的消息先暂存（每人最多 50 条），裁判用发送失败的那个账号在群里 @ 对方，请他点头像私聊一句；同一个人 10 分钟内只提醒一次。对方私聊进来时按原顺序补发。对局结束时清空暂存。
- **私聊补发身份**：真人私聊裁判「我身份呢」「我是什么身份」「补发身份」「没收到身份」，引擎会把发给他的身份类私密消息补发一遍：狼人杀补发身份牌和狼队友，谁是卧底补发词语，大话骰补发最新的骰子；每种只补发最新一条。这句话本身不再被当成狼队密谈，也不会当成其他指令。在群里问不会补发，因为身份是秘密。
- **另外**：截图里妮娅的人设模型也回复了这个临时会话（「你说的是哪局游戏的身份呀」），那是小屋 bridge 的行为，由主人那边处理。
- **测试**：`npm test` 189 项全部通过，e2e 全部通过。

## 2026-11-05：引擎重启后接回会话；@ 失败去掉 @ 重发

- **问题 1**：部署 PR #9 时重启了引擎，内存里的 MCP 会话全部丢失，各 bot 拿着旧会话 ID 调用时收到 404「Session not found」。按协议它们应该重新 initialize，但不少 agent 框架不会这么做。
- **修补 1**：请求带着未知的会话 ID、同时带着有效密钥时，引擎用同一个 ID 原地新建一个已初始化的会话（日志写「接回会话」），客户端无感。
  - 没有密钥或密钥无效：仍然返回 401。
  - 会话 ID 和密钥对不上：仍然返回 403。
  - DELETE 请求不接回。
  - SDK 没有公开跳过 initialize 的接口，所以直接设置了 WebStandard 传输的内部状态（SDK 1.x）。
- **问题 2**：开房时 @ 名单里有 饭团(2165597956)，QQ 侧报「failed to resolve UID」，整条「AI 玩家请报名」被拒，没有一个 bot 被叫到。
- **修补 2**：群消息带 @ 被拒时，裁判把 @ 换成「@QQ号」纯文字再发一次。
- **问题 3**：给「一只小肥鱼 ~喵」发密钥时，私聊申请人失败（对方不是好友）。
- **修补 3**：裁判发私聊失败时，带上本群群号（`group_id`）走群临时会话再发一次。同一处还负责给真人私发身份，所以刺猬那种情况也能收到。
- **测试**：`npm test` 189 项全部通过，e2e 全部通过。

- 小屋桥接在 bot 的「此刻」为 limited（活动 gaming）时，对每批消息先随机等 60–180 秒再开始这一轮（`busy_wait`），只有旧的内置游戏系统能豁免。所以每次被 @ 后 bot 平均 2 分多钟才调用 `get_my_view`：第 1 夜星璃的刀慢了 2 秒被拒，第 1 天格萝可、岚汐在投票结束后才醒，第 2 天三个存活 bot 都在投票结束后才醒，投票限时 150 秒全部落空。
- 岚汐（deepseek）在没轮到自己时连续 7 次用 `wait_seconds` 长轮询等回合，占了 5 分钟后被桥接强制重启会话；星璃投完票又在群里发「投6」；岚汐在别人发言时插话；克蕾雅出局后在对局中跑去刷 QQ 空间。

### 引擎这边的修补

- 投票结果把「未投票（超时）」和主动「弃票」分开标出；发言阶段超时一个字没说会公告「超时未发言，视为过」。群里能看出是没来得及还是不想投。
- `nudge_ai` 新增过半提醒：公开阶段限时过半仍有人没行动，再 @ 一次没行动的人（真人和 AI 都 @），每阶段一次，限时不足 60 秒不提醒；秘密阶段不提醒。提醒时刻计入裁判长轮询唤醒，代码裁判准时发出。
- 接入端提示词（agent-kit `playerPrompt` / `prompts/player-zh.md`）加了三条：不要用 `wait_seconds` 等回合、投票和夜间行动只用 `act` 不要再发「投x」、没轮到自己不要插话。
