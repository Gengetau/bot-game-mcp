# 开发进度与测试记录

## 2026-11-04：v0.1.0 首个完整版本

### 已完成

- **引擎核心**（`src/core`）：
  - **大厅与报名**：AI 可选玩家、裁判或「都行」；真人通过裁判转交「加入」报名。
  - **抽签与座位**：程序抽签选裁判，随机分配座位。
  - **推进与投递**：阶段门控、超时托管、最短时长；按序投递并保证发言间隔。
  - **轮询与视角**：长轮询；玩家、裁判、旁观者三种视角，以及赛后完整复盘。
  - **裁判容灾**：候补裁判可以接管失联的裁判。
  - **存档**：原子写入，重启后对局继续。
- **游戏**（`src/games`）：
  - 狼人杀：6~16 人。角色有预言家、女巫、猎人、守卫、白痴，6~12 人有预设板子，支持屠边或屠城、PK、遗言。
  - 谁是卧底：4~12 人，内置 250 组词，支持白板。
  - 大话骰：2~8 人，1 点可当任意点数，按命数淘汰。
  - 数字炸弹：2~20 人，单局或淘汰制。
- **MCP 层**（`src/mcp`）：
  - 17 个工具，全部带注解。
  - 3 份指南资源，加上规则资源模板。
  - 2 个提示词：裁判、玩家。
  - 认证：keys、open、admin 三种模式。
  - 消息渲染：text、CQ 码、OneBot v11 三种格式。
- **传输**（`src/server`）：Streamable HTTP、旧版 SSE、stdio、bridge（stdio 转 HTTP），以及只读观战 API。
- **工具链**：
  - 命令行：serve、stdio、bridge、simulate、gen-key、init-config。
  - 离线模拟器：真人操作用自然语言模拟。
  - 文档生成：`npm run docs`。
  - CI：Node 22 和 24，跑类型检查、测试、构建、CLI 冒烟测试，并检查生成的文档是否最新。

### 独立代码审查与修复

一个只读的审查 agent 审查了全部代码，报告的问题均已修复，并补了回归测试：

| 问题 | 修复 |
|---|---|
| open 模式下，用真人的 QQ 号 `login` 可以读到真人座位的私密视角 | `getView`/`getLog` 只认 AI 座位；`login` 拒绝正在参赛的真人 QQ 号 |
| 狼人杀「第N夜·女巫」阶段只在女巫存活时出现，泄露女巫死活 | 只要板子里有女巫就每晚都开女巫阶段 |
| 夜晚结束得快慢会泄露神职死活 | `night_min_s` 默认改为 20 秒 |
| 猎人是最后一个神职时先判胜负、不开枪，规则文本没写清楚 | 保留「胜负判定优先」，在规则和猎人说明里写明 |
| 狼人杀 PK 后议程里会残留重复的夜晚步骤 | 夜晚步骤只入队一次 |
| 「投资有风险，我觉得3号可疑」被识别成投 3 号 | 指令目标必须出现在开头；狼人杀支持「投给3号」 |
| 程序自动主持的对局可以被接管；任何非玩家都能接管 | 自动主持的对局拒绝接管；只有候补裁判或管理员能接管 |
| 中止后的对局对所有人公开私密日志 | 只有正常结束的对局公开完整复盘 |
| 空闲中止的对局不会在群里公告 | 进行中的对局中止时统一由裁判发出公告 |
| 任何人都能移除别人的候补裁判 | 只能移除自己，或由房主、管理员移除 |
| `since_seq` 大于游标时会跳过未发出的消息 | `since_seq` 只能用于重发 |
| 昵称或发言里的 `{@N}`、`[CQ:…]` 会变成真实的 @ 或 CQ 码 | 写入前清洗；text 格式输出时也让 `[CQ:` 失效 |
| 大话骰「叫到3个5」无法识别 | 前缀改为最长优先匹配 |

额外改进：

- 转交真人消息时，自动去掉开头的「回复」引用和 @裁判；
- 模拟器不再把等待夜晚最短时长误计为超时托管。

### 已知限制

见 README「已知限制」：

- 裁判能看到发给真人的私聊；
- QQ 私聊需要好友关系，或使用群临时会话；
- 一个群同时只能有一局；
- 狼人杀连续 6 个昼夜无人死亡判平局；
- 只支持单实例部署；
- 报名超时不在群里公告。
