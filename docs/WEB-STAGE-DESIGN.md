# 网页舞台 + 规则状态层：设计稿

> 状态：**已确认**（2026-11-08）。第八节的问题主人和缪斯都已答复，结论写进了正文。页面 UI 先请 GPT 出设计图，再照设计图实现（见第三节第 8 小节）。
> 背景：
> - 缪斯的《后两本卡点说明》（同学会 A1–A6、804 D1–D3）；
> - 主人的想法：剧本杀不一定在群里玩，可以放到网页上。
>
> 主人已定：
> 1. 基本上是 bot 在玩，真人主要观战；
> 2. bot 的发言原样转发一份到 QQ 群，不做摘要；
> 3. 网页端和二期规则状态层合在一起设计；
> 4. 网页端不只给剧本杀用，以后不方便在群里展示的游戏也放进来；
> 5. 要注意 UI 体验。

## 一、目标与边界

**目标**
- 给引擎加第二个「舞台」：网页。一局游戏可以在群里进行（现状），也可以在网页上进行。
- 网页舞台是通用框架：外壳（阶段、倒计时、座位、讨论流、记录）所有游戏共用，每个游戏只写自己的面板。
- 剧本杀是第一个用户。同学会需要的规则状态层（签约、指认、禁投、关键词技能）一起做，因为这些机制在网页上最自然：私下选择就是按钮，指认就是点人。

**不变的东西**
- 四个不变量一条都不改：程序决定一切；裁判只是消息总线；阶段门控；状态可序列化。
- 网页是**纯前端**。它读的视图和 MCP 里 `get_my_view` 是同一套函数：`publicView` 给所有人，`privateView` 只给本座位。网页不能有影响结果的接口，真人观众在网页上什么都改不了。
- bot 的接入方式不变，仍然走 MCP。对 bot 来说，「在群里玩」和「在网页上玩」的区别只有一条：发言不再自己发到群里，而是交给引擎（见第四节）。

**不做**
- 不做网页上的真人玩家座位（一期）。真人主要观战；以后需要再加，接口留好位置。
- 不做网页版的狼人杀、谁是卧底。它们的乐趣在群聊气氛里，继续留在群里。

## 二、整体结构

```text
bot（MCP 客户端） ──MCP──▶  引擎  ◀──HTTP/SSE──  网页（观众，只读）
                             │
                             └──outbox──▶ 裁判 ──▶ QQ 群（镜像：开场、发言、结局）
```

- **舞台选项**：每种游戏在定义里声明支持哪些舞台（`stages: ['group']`、`['group','web']` 或 `['web']`）。开房选项 `stage` 选择本局用哪个，剧本杀默认 `web`，其他游戏默认 `group`。
- **群舞台**：和现在完全一样。
- **网页舞台**：
  - 所有游戏内容都在网页上展示，包括幕文本、线索图、搜证、问卷和讨论；
  - QQ 群只收镜像：开场公告和观战链接、每条公开发言、阶段切换的一行提示、结局；
  - 私密内容只发给对应的 bot，走 MCP 视图和私聊事件，**永远不进群、不进公开网页**。
- **阶段门控**：在网页舞台上，「开放」不再等裁判把群消息发完，而是等网页事件写入日志。群镜像是尽力而为的旁路，发慢了不拖住游戏。要实现这一点，outbox 里的镜像消息要标成「不门控」。

## 三、网页端 UI

主人特别提到 UI 体验，这一节写细一点。原则：**像看一场演出，而不是看日志**。

### 1. 设备和入口

- **手机优先**：大部分人会在 QQ 里点链接打开，也就是在手机上竖屏看。所有布局先按 360px 宽设计，再放大到平板和桌面。
- **入口**：开局时裁判在群里发观战链接，链接带本局的观战令牌（见第六节）。点开就能看，不用登录。
- **浅色、深色两套主题**，跟随系统，也可以手动切换。尊重系统的「减少动态效果」设置。

### 2. 页面外壳（所有网页游戏共用）

手机竖屏从上到下：

1. **顶栏**：游戏名、剧本名、当前幕和阶段（如「第二幕 · 搜证」），右侧是倒计时环。倒计时用引擎给的 `deadline`，最后 30 秒变色。
2. **座位条**：横向滑动的头像列表。头像用室友的形象图，每人一个固定的座位色。状态直接画在头像上：正在发言是光圈，已行动是小勾，出局是灰。点头像弹出这个人的公开信息卡：角色名、公开的线索、发言次数。
3. **主区域**：分页签，默认是「讨论」。
   - **讨论**：聊天气泡，左边是头像和座位色，右上角是时间。bot 正在生成时显示「3号 克蕾雅 正在思考…」。程序的旁白（幕文本、阶段提示）用居中的叙事卡片，和气泡明显区分开。
   - **游戏面板**：每个游戏自己的内容，剧本杀见下。
   - **记录**：完整的公开事件时间线，可以筛选，比如只看投票、只看公开的线索。
4. **底部提示条**：一句话说明现在在等谁、等什么，例如「等待 2 人完成搜证」。

桌面宽屏：座位放左栏，讨论在中间，游戏面板固定在右栏，三栏同时可见。

### 3. 剧本杀面板

- **剧本封面**：开场是全屏封面，包括剧本名、简介、人数和角色卡片墙。每张角色卡有角色名、一句话介绍和对应的 bot 头像。点「开始观看」进入主页面。
- **幕文本**：每幕的公共阅读文本做成可以展开的「书页」卡片，正文用衬线字体排版，有段距，配图点开可以全屏看。
- **搜证地图**：
  - 地点做成卡片网格，每个地点显示剩余卡数（如「书房 · 剩 3 张」）；
  - 有人搜证时，那张地点卡闪一下，并标出搜的人的头像，对应「群里播报谁搜了哪里」的规则；
  - 卡面不显示。观众只看得到卡背的类别标签，比如「尸体线索」。
- **线索墙**：被公开的卡翻面展示，有翻牌动画，配图和文字都在上面。每张卡注明谁在第几轮公开的。没公开的卡在比赛中**完全不出现**在公开视图里，包括数量也只按地点给。
- **问卷 / 投票**：作答期间只显示「已作答 4/6」。截止后逐题揭晓：
  - 先亮出正确答案，再按人翻开各自的选项，答对的高亮；
  - 最后是破案结果和 MVP。
- **结局**：全屏结局卡和真相文本，之后进入复盘（见第 6 小节）。

### 4. 讨论区的节奏

bot 生成一条发言要几秒到几十秒，直接刷屏会很乱。所以：

- 新消息带入场动画，自动滚到底部。用户自己往上翻的时候不自动滚，底部出现一个「有 3 条新消息」的按钮。
- 长发言默认折叠到 8 行，点开看全部。
- 发言里的「3号」「@克蕾雅」这类称呼自动高亮成对应的座位色，方便看出谁在说谁。

### 5. 状态和异常

- **断线重连**：网页按事件序号续传，不会丢消息，也不会重复显示。
- **加载**：用骨架屏，不显示空白页。
- **对局中止**：显示中止原因和已经发生的公开内容。
- **链接失效或者错误**：给出明确的中文提示。

### 6. 复盘（对局结束后）

- 「上帝视角」开关：结束后，每个人的私密信息、私下选择、搜到的卡都可以看。**只在复盘回放时开放，对局中谁都没有上帝视角，主人也不例外**（主人定）。正常结束的局才开放，这和现在 `/api/games/:id` 的口径一致；中止的局仍只给公开记录。
- **时间轴回放**：拖动进度条，从任意时刻重看讨论和事件，可以 1×、2×、4× 播放。
- **每个角色一个页签**：这个 bot 看到了什么、做了什么，便于看出它为什么那样推理。

### 7. 实现方式

- 网页由引擎自己托管，路径 `/web/`，和 MCP 用同一个端口。观战走现在的公网地址，不额外开端口。
- 前端用 TypeScript 编译出的静态文件，加一个很小的组件库（如 Preact），依赖全部打包进仓库产物，**不从 CDN 加载**：既不依赖外网，也不把观众的访问暴露给第三方。
- 视觉：暖色纸张感的配色，和小屋的气质一致；中文字体用系统字体栈，标题可以用衬线体。所有颜色都定义成主题变量。
- 每个网页游戏注册一个面板组件；外壳负责连接、倒计时、座位、讨论流和记录。以后加新游戏，只写面板。
- **验收**：用 Playwright 在手机宽度（360、390）和桌面宽度下截图，人工过一遍再合并；另加一个从开局到结局的端到端测试。

## 四、讨论模型和群镜像

### 1. 发言怎么进来

- 网页舞台上，bot 的 `selfPost` 强制为关：bot 不自己往群里发言，而是调用 `act({action:"speech", text})` 交给引擎。引擎把发言写进公开日志，网页立刻显示。
- 现在的「轮流发言」照常可用，每人每轮一次。

### 2. 自由讨论环节（新）

804 那种自由对戏、同学会第二幕的讨论，用轮流发言不自然。新增一种阶段 `free_talk`：

- 在时限内所有人都可以发言，不排队；
- 每人每条之间至少隔 N 秒，整个环节最多 M 条，防止 bot 刷屏，也控制 token 开销；
- bot 通过现有的长轮询（`waitForTurn`）拿到新消息，自己决定要不要接话；
- 时间到或者所有人都声明「说完了」就结束。

agent-kit 的提示词和 `prompts/player-zh.md` 要同步加上自由讨论的说明，这两处有测试保证一致。

### 3. 群镜像

主人定了：发言原样转一份到群里，不做摘要。

- **谁来发**：
  - 发言的 bot 在裁判的嗓子账号里（`voices.json`）时，用它自己的 QQ 号发，群里看起来就是她本人在说；
  - 否则由裁判账号发，前面加「【剧本杀】3号 克蕾雅：」。
- **发什么**：开场公告和观战链接、每条公开发言、阶段切换的一行提示（如「第二幕 · 搜证开始」）、被公开的线索**只发标题**（主人定）、结局和真相链接。幕的长文本和线索图**不往群里发**，只在网页上看，否则群会被刷屏。
- **只发公开事件**：镜像只取 `audience: public` 的事件，这和现在发往群的过滤口径一致，私密内容不会进群。
- **限速**：QQ 有发送频率限制。镜像发言排队发，每条之间至少隔几秒；积压太多就把连续的发言合并成一条转发记录，不能丢。

### 4. 游戏期间群里的规矩

游戏不在群里进行了，群里就不需要为了游戏禁言旁观者。但有一个风险：参赛的 bot 在群里闲聊时，可能把自己的私密信息说出来，比如「我签约了」，别的参赛 bot 在群里看到就串了。

**主人定**：
- 旁观者在群里随便聊；
- 参赛的 bot 在群里说话，沿用现在夜间「撤回 + 提醒」那一套，提示「对局进行中，请在网页里发言」；
- 镜像消息本身不算违规。

## 五、规则状态层（二期）

对应同学会的 A1–A5。原则不变：**用数据包里声明式的字段表达，配一张固定词汇的效果表，不引入脚本语言**。剧本作者写不出程序判不了的东西，程序也不会执行任意逻辑。

### 1. 状态标记

- 每个座位一组标记 `flags`，值是布尔、数字或座位号，例如 `signed: true`、`lover: 3`、`can_accuse: 1`（次数）。
- 标记存在 `rec.state` 里，可以序列化。
- 标记默认是秘密，只有本人和复盘能看到。公开的标记（例如「董阳选了哪一侧」）在数据包里写 `public: true`。

### 2. 新的环节类型

| 环节 | 用途 | 秘密性 |
|---|---|---|
| `choice` 私下选择 | 每人从选项里选一个，选完设标记。例：签约 / 不签约 | `secret: true`，有固定最短时长，所有人同时进行；环节是否出现、时长都不随选择变化 |
| `ask` 定向问答 | 每人私下答一道题（题目可以按角色不同），答对执行效果。例：第二幕支线问答，答对得到指认权 | 同上 |
| `target_choice` 选人 | 指定的角色选一名玩家，设标记。例：子晴「我们恋爱吧」 | 视数据包而定 |
| `public_choice` 公开选择 | 指定角色当众二选一，结果公布。例：董阳「爱我的和我爱的」 | 公开 |

`ask` 的判分复用问卷的代码。

### 3. 条件私发

幕的私密文本和私密图片可以写多个版本：

```json
"private": {
  "胡贺": [
    { "when": { "flag": "signed", "is": true }, "text": "你的新身份是……" },
    { "text": "你没有签约。小道消息：……" }
  ]
}
```

按顺序取第一个条件成立的版本。没有条件的那个版本是默认值。

### 4. 效果表（固定词汇）

| 效果 | 说明 |
|---|---|
| `set_flag` | 设置或增减一个标记 |
| `give_clue` | 私发一张卡（复用搜证的发卡） |
| `tell` | 私发一段文本 |
| `reveal_identity` | 公布某人的真实身份（公开事件） |
| `open_quiz` | 开一道全员单题竞猜（复用问卷），每人一次 |
| `forbid_vote` | 加一条投票约束（见第 6 小节） |

### 5. 触发器

- **指认**：持有 `can_accuse` 的玩家，在指定环节可以执行 `accuse` 动作，指认某人。
  - 程序检查被指认者的标记，例如 `signed`。指对了，对 TA 执行 `reveal_identity`，并去掉 TA 的指认权；指错了，对自己执行 `reveal_identity`。
  - 「说谎」就是「以签约换来的新身份示人」，不是发言内容撒谎（缪斯对照组织者手册确认）。签约台词里写明签约的权益是「可以拿新身份向同学们介绍自己」「可以在游戏中说谎」；不签的人才「不能在指向性证据前说谎」。指认的结算也只围绕真实身份公布。所以按 `signed` 标记判定，不用降级。
  - 原文细节：指认权**答对获得、答错丧失**（定向问答答错，执行 `set_flag can_accuse 0`）；**行使是自愿的**，持有者可以一直不用。
- **关键词技能**（A3）：数据包列出关键词、持有者和效果。防误触口径：
  1. 只认**别人**的公开发言，持有者自己说出来不触发；
  2. 归一化之后整词匹配，同义词在数据包里列全；
  3. 每个技能每局只触发一次；
  4. 只在讨论类阶段监听，私聊和旁白不算；
  5. 触发时只私发给持有者，并写进复盘日志。
- **马思明的监控竞猜**：关键词触发 `open_quiz`。唯一答案是 22:30，每人一次，全错则这张线索沉底。

### 6. 投票约束（A4）

- 约束写成「当某条件成立时，A 不能选 B」。
- 作用在投票选项上。同学会的结局是公聊后投票投真凶，一锤定音，没有问卷、积分和多结局（缪斯确认）。
- 例子：姐妹互禁是开局即有的固定约束；恋爱是 `target_choice` 设下 `lover` 后加的约束；董阳的二选一是 `public_choice` 之后，对被选的那一侧加约束。
- 网页上，被禁的选项灰掉并注明原因。bot 的行动面板里，这些选项直接不出现。

### 7. 说谎许可和帮凶（A5）

- 这些都是数据：写在本人的私密文本里，用秘密标记记着，程序不公开。
- 「不能在指向型证据面前撒谎」程序判不了，作为荣誉规则写进 `rules_note`。

### 8. 小剧场（A6）

建议做成一次轮流发言：每人的提示里附上自己那句台词，网页上用「剧场」样式展示，带台词框和角色名。不需要新机制。

### 9. 校验

`check-script` 要能查出：
- 条件引用了不存在的标记；
- 效果引用了不存在的卡或角色；
- 关键词与关键词、关键词与常用词冲突，给出 ⚠️；
- `choice` 环节没有设置最短时长。

## 六、安全

- **令牌**：
  - 每局一个随机观战令牌，链接里带着。它只能看公开视图，对局结束后可以看复盘。
  - 主人有一个单独的管理令牌，从配置读，不进链接。它在对局中和普通观战一样只看公开视图，结束后可以看复盘；中止的局也能看完整复盘，便于排查。
  - 令牌只用于网页，和 MCP 密钥完全分开，网页上没有任何工具调用。
- **图片**：经过引擎代理，按令牌检查可见性。没公开的卡面图，比赛中不可能通过猜地址拿到。云盘的原始地址不出现在页面上。
- **转义**：所有玩家文字先过 `sanitizeUserText`，渲染时一律当纯文本，不拼 HTML。页面加严格的 CSP。
- **限流**：观战接口按 IP 限流，单局连接数设上限。
- **不暴露管理功能**：`publicApi` 的旧接口保持现状；网页接口在单独的路径前缀下，只读。

| 期 | 内容 | 验收 |
