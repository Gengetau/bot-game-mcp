# 剧本杀扩展设计稿：搜证 + 问卷结算（草案）

> 状态：**草案，待主人确认**，还没有动代码。
> 背景：045《夜总会杀人夜》是「分节阅读 + 投票」，现在的引擎够用。但 371《讲台上的乌鸦》有三轮搜证、用问卷结算，txh《同学会》有四轮搜证、76 张图文卡，现在的引擎都承载不了。见 2026-11-07 缪斯的《同学会》盘点。
> 目标：先加两样**通用能力**，以后的剧本大多会用到；只服务单个剧本的特殊机制不进引擎。

## 〇、剧本类型和本期落点（缪斯 2026-11-07 的分类）

按主流程骨架，目前手上的 4 本分成 4 类：

| 类型 | 代表 | 引擎怎么承载 |
|---|---|---|
| 1. 线性分幕型 | 045 | 现在的引擎原生支持，首局已跑通 |
| 2. 搜证轮次型 | 371；《同学会》的骨架也是这一类 | **本期**：新增搜证原语（选点、限次、线索归属、私密持有与自愿公开、点数配额） |
| 3. 分支状态型 | 《同学会》 | 二期：单独做一层规则状态机，包括玩家状态与权限、条件发放、事件触发、动态投票约束。不往数据包字段里硬塞 |
| 4. 演绎主导型 | 804 | 不改骨架，只加强 DM 工具（本期加一项「DM 发放」，见第三节） |

另有两个维度不影响上面的分类：
- 结算方式：投票（045、《同学会》）、问卷计分（371，本期）、无硬结算（804）；
- 线索载体：纯文本或图文卡。图文卡的发放层已经打通。

## 一、改动范围

| 做 | 不做（本期） |
|---|---|
| 线索卡、搜证环节、行动点、深入卡、公开线索 | 口头关键词触发的技能（误触发风险高，045 的 FAQ 踩过坑） |
| 问卷结算：多道选择题、计分、按问卷判定破案 | 动态禁投（姐妹互禁、恋爱禁投等），改为写进角色本自觉遵守 |
| 难度调节卡的开关（开房选项） | 支线问答赢「身份指认权」 |
| | 签约这类「私下二选一」分支，二期再做，见第六节 |

**兼容**：新字段全部可省略。不写 `clues` 和 `questionnaire` 的剧本（如 045）流程完全不变。

## 二、数据包新增字段

```jsonc
{
  // ……原有字段不变……

  "search": {
    "points": 12,              // 每人整局的行动点总数
    "carry_over": true,        // 本轮没用完的点数留到下一轮（false = 作废）
    "exclusive": true,         // 一张卡被搜走后，别人就搜不到了（实体卡规则）
    "self_search": false       // 能否搜「属于自己」的线索（一般不能）
  },

  // 搜证地点。人物也可以被搜：clues[].at 直接写角色 key 即可，不用登记在这里
  "locations": [
    { "key": "room401", "name": "401 房间" },
    { "key": "body",    "name": "尸体" },
    { "key": "monitor", "name": "酒店监控室" }
  ],

  "clues": [
    {
      "id": "c401_knife",      // 字母、数字、_、-
      "at": "room401",         // 地点 key 或角色 key（= 卡背上的归属）
      "round": 3,              // 第几轮搜证开始能搜到（对应 acts[].search.round）
      "cost": 1,               // 花几个行动点，默认 1
      "title": "401·水果刀",   // 卡背标签：搜之前别人能看到的名字，不能剧透
      "text": "卡面文字（只发给搜到的人）",
      "images": ["clue_401_03"],   // 卡面图，引用 images[].id；caption 要写全图上的信息
      "deep": ["c401_knife_2"],    // 拿到本卡后可以「深入」的后续卡（见下）
      "deep_only": false,          // true = 只能通过深入拿到，不在地点里直接搜到
      "level": "hard",             // 可选：难度调节卡，开房选项 clue_level 决定发不发
      "public": false              // true = 搜到后自动在群里公开（如公共物证）
    }
  ],

  "acts": [
    {
      "title": "第三幕",
      // ……public / private / 图片照旧……
      "search": {
        "round": 3,            // 本幕开放第几轮的线索（可以开放多轮，写数组 [3, 4]）
        "max_points": 3,       // 本轮每人最多花几点，省略则只受总点数限制
        "minutes": 5           // 搜证限时
      }
    }
  ],

  // 写了 questionnaire 就用问卷代替原来的一道投票题
  "questionnaire": [
    {
      "id": "q_culprit",
      "question": "谁是杀死蒲老师的真凶？",
      "options": "roles",          // "roles" = 选项为全部角色；也可以写 [{ "key": "a", "text": "……" }]
      "answer": ["ruoji"],         // 正确选项（可多个）
      "points": 10,
      "culprit": true,             // 判定破案的那道题：多数人答对即破案
      "for": []                    // 只给这些角色作答，空 = 所有人
    },
    {
      "id": "q_method",
      "question": "致死手法是？",
      "options": [{ "key": "a", "text": "氰化氢中毒" }, { "key": "b", "text": "麻药控制后凌迟失血" }],
      "answer": ["b"],
      "points": 5
    }
  ]
}
```

**校验规则**（check-script 会检查）：
- `at` 必须是 `locations` 里的 key 或角色 key；
- `deep` 和 `images` 引用的 id 必须存在，深入链不能成环；
- 每个 `round` 至少有一幕开放它；
- 问卷的 `answer` 必须在 `options` 里，至多一道题标 `culprit`；
- 有 `clues` 时 `search.points` 必须大于 0。

## 三、流程

每一幕变成：**播报 / 私发 → 阅读 →（如有）搜证 → 自由讨论**。

### 搜证环节

秘密阶段，限时 `minutes`。所有人同时行动，私聊裁判或调用 MCP：

| 动作 | MCP | 真人私聊 | 说明 |
|---|---|---|---|
| 搜地点 | `act({"action":"search","text":"room401"})` | `搜 401房间` | 从该地点本轮还剩的卡里随机抽一张（随机走 `this.rng`）。地点名和角色名都能识别 |
| 搜人 | `act({"action":"search","target":3})` | `搜 3号` | 搜「属于」3 号所扮角色的卡 |
| 深入 | `act({"action":"deep","text":"c401_knife"})` | `深入 水果刀` | 花点数拿后续卡，只能深入自己持有的卡 |
| 结束 | `act({"action":"skip"})` | `搜完了` | 本轮不再搜；点数按 `carry_over` 处理 |

- 搜到的卡**只私发给本人**：文字、图片和 caption。
- 群里只播报「3号 搜了 401 房间」，**不播报卡面**。是否连地点也隐藏，见第七节问题 4。
- 所有人用完本轮点数或「搜完了」，或者到时间，环节就结束。超时不代搜，点数按 `carry_over` 处理。
- 搜证环节固定出现，标题、时长不随谁搜到什么而变化，符合项目「秘密阶段」不变量。

### 公开线索

讨论中，持卡人随时可以把自己的卡公开到群里，公开后所有人的视图里都有这张卡：
- MCP：`act({"action":"share","text":"c401_knife"})`
- 真人私聊：`公开 水果刀`

这对应线下「把卡亮出来」。

### 视图

- 玩家 `get_my_view` 的 `you.search` 里有：剩余总点数、本轮可用点数、各地点和各人还剩几张卡（只有数量和卡背标签）、我持有的卡（全文）、可以深入的卡。
- 公开视图 / `publicView`：只有各地点剩余张数、谁搜了哪里、已公开的卡。**没有**任何未公开卡的内容。
- DM：能看到全部卡、谁拿了哪张。

### 问卷结算

替代原来的投票环节，限时 `vote_timeout_s`。
- 每人逐题作答，题目和选项来自数据包。
- `act` 的入参没有数组字段，所以每次调用答**一道题**，题号和选项编码在 `text` 里：
  - MCP：`act({"action":"answer_q","text":"1:ruoji"})`，题号也可以写题目 id。
  - 真人私聊：`1 若寂`、`2 b` 之类。
  - 截止前可以重答，以最后一次为准。
  - 视图里的 `todo` 列出还没答的题，全部答完就算完成。
- 答案私下提交，全部收齐或超时后统一公布。
- 公布每题正确答案、每人得分。
- `culprit` 题多数人答对即为破案：之后照旧凶手坦白 → 真相 → 结局。
- 胜负：
  - 破案时侦破方胜，否则凶手胜；
  - 另外公布得分最高的人（MVP）。

### DM 发放（给第 4 类剧本和 DM 临场判定用）

有 DM 时，DM 可以把一张线索卡交给某位玩家，不花点数：
- MCP：`act({"action":"give","target":3,"text":"c401_knife"})`
- 真人私聊：`给3 水果刀`

被交出的卡从地点里移除。只能交出本轮已开放的卡，DM 不能凭空造内容。

### 开房选项（新增）

| 选项 | 默认 | 说明 |
|---|---|---|
| `search_timeout_s` | 300 | 搜证限时（剧本里 `acts[].search.minutes` 优先） |
| `clue_level` | `normal` | `easy` 发 `level:"hard"` 以外的卡加上提示卡；`normal` 全发；剧本可自定义 |

## 四、保密与安全

- 卡面文字和图只走 `tell`（私聊），公开视图有测试覆盖，结束前不得出现任何未公开卡的内容。
- 卡背标签 `title` 是公开的。录入时要确保不剧透，check-script 会提醒标签不要和凶手的角色名重合。
- 结束时可以选择公布「没被搜到的线索」：开房选项 `reveal_unfound`，默认开。

## 五、给缪斯的录入说明（371 / txh）

1. 先按原剧本的搜证轮次，把每张卡归到 `at`（地点或角色）和 `round`。
2. 卡面图放云盘剧本文件夹，`images` 登记，`caption` 写全图上的文字。卡背标签写进 `title`。
3. 「深入」卡：在父卡的 `deep` 里列出，子卡标 `deep_only: true`。
4. 难度调节卡标 `level: "hard"`。
5. 结算：
   - 371 用 `questionnaire`；
   - txh 写一道 `culprit` 题即可，也可以加动机、手法题。
6. txh 的「签约」先降级：
   - 第一幕私密文本里直接写明「你已签约 / 未签约」，按原剧本默认路线写；
   - 小道消息作为 `acts[0].private` 发给对应角色；
   - 等第六节的二期能力上线后再改回分支。
7. 砍掉的机制（指认权、关键词技能、动态禁投、22:30 竞猜）在 `rules_note` 或 `host_notes` 里写明「本版省略」。

## 六、二期（本期不做）：规则状态层

第 3 类剧本（《同学会》）需要四样东西，这已经超出数据包能表达的范围，要单独设计一层规则状态机，不在 JSON 字段里硬凑：
- 玩家状态和权限，比如签约后可以说谎；
- 条件发放，按状态替换后续私发的内容；
- 事件触发，比如一次性竞猜、按条件发线索；
- 动态投票约束，比如互禁投。

等搜证和问卷跑通后再出设计稿。

## 七、需要主人拍板的问题

1. **卡是否独占**（`exclusive`）：实体卡规则是被搜走就没了。我建议默认独占，剧本可以关。
2. **没用完的点数**：默认留到下一轮。
3. **能否搜自己**：默认不能。
4. **群里是否播报「谁搜了哪里」**：
   - 线下桌上大家看得见谁去搜了哪里，我建议播报地点、不播报卡面；
   - 想更隐蔽，就只播报「3号 完成搜证」。
5. **问卷胜负**：
   - 我建议：破案与否定阵营胜负，另外公布 MVP；
   - 也可以纯按分数排名，不分阵营。

确认后的实现顺序：
1. 数据格式 + check-script；
2. 搜证环节 + 公开线索；
3. 问卷；
4. 演示剧本加两轮搜证和问卷，补测试（泄露检查、随机对局）；
5. 文档。
