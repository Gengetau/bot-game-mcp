# 剧本杀（jubensha）：数据包格式与运维说明

剧本杀由两部分组成：

- **程序**负责骨架：
  - 选角；
  - 开局私发人物剧本，之后按幕私发线索；
  - 计时；
  - 投票、计票；
  - 让凶手坦白，最后公布真相。

  胜负完全由程序按数据包判定。
- **DM（可选）**负责串场：
  - 念白、渲染气氛；
  - 私下回答玩家提问；
  - 提前进入下一环节、延长时间。

  DM 没有任何能改变结果的接口。

## 一、隐私红线

1. **数据包绝不能提交进本仓库。** 剧本通常是商业作品，文件里还含有全部真相。仓库里只有原创的演示剧本 `packages/engine/examples/jubensha/demo-rainy-bookshop.json`。
2. 数据包放在服务器上的私有目录，由配置项 `scriptsDir`（或环境变量 `BOTGAME_SCRIPTS_DIR`）指定。**这个目录不能在任何 bot 能读到的路径下**，否则 bot 能直接翻到真相。
3. 程序保证不泄露秘密：
   - 人物剧本、每幕的私密线索只私发给对应角色（真人走裁判私聊）。
   - 认罪书只在坦白环节发给凶手。
   - 真相和主持手册只有 DM 能看到，结束时才在群里公布真相。
   - 公开视图和群消息在结束前不含任何秘密，有测试覆盖。
4. 对局复盘写进 bot 记忆时，需要标注为「演出」。这件事由小屋那边的记忆模块负责，不在引擎里做。

## 二、数据包格式

一个剧本对应一个 UTF-8 JSON 文件，扩展名必须是 `.json`。放进 `scriptsDir` 后立即生效，不用重启；改了文件也会按修改时间自动重新加载。

```jsonc
{
  "id": "045",                 // 开房时 script=045；只能用字母、数字、_、-
  "title": "剧本标题",
  "players": 6,                // 玩家人数（不含 DM），必须等于 roles 数量
  "summary": "一句话简介，公开，不能剧透",
  "intro": "开场念白/故事背景，开局时群里播报",
  "rules_note": "本剧本特有规则（可空）",
  "roles": [
    {
      "key": "lin",            // 角色代号，字母数字，在 acts.private、culprits、开房选项 cast 里引用
      "name": "小林",
      "gender": "female",      // male / female / any，仅供参考
      "public": "公开介绍：所有人都能看到",
      "script": "人物剧本：开局私发给扮演者（最长 20000 字，超过 1500 字会自动分段发）",
      "confession": "认罪书：只有凶手需要，坦白环节才发给他"
    }
  ],
  "acts": [
    {
      "title": "第一幕：案发",
      "public": "本幕开始时群里播报的公开内容（可空）",
      "private": { "lin": "只发给小林的线索", "zhou": "只发给周先生的线索" },
      "discuss_minutes": 10    // 本幕自由讨论时长，可省略（用开房选项 discuss_minutes）
    }
  ],
  "vote": { "question": "谁偷走了《雨窗集》？" },
  "culprits": ["lin"],         // 凶手角色 key，可多个；得票最多且唯一的人是其中之一即算破案
  "truth": "真相全文，结束时公布",
  "endings": { "solved": "破案结局念白", "unsolved": "凶手逃脱结局念白" },
  "images": [                 // 图片线索（可省略）。文件放在素材库里与 id 同名的文件夹，如 045/地图.jpg
    { "id": "map", "file": "地图.jpg", "caption": "图片的文字说明：AI 玩家只看得到这段，要写全图上的关键信息" }
  ],
  "intro_images": ["map"],    // 开场念白后群发
  // roles[].images：随人物剧本私发；acts[].public_images：本幕群发；
  // acts[].private_images：{"角色key": ["图片id"]} 本幕私发；truth_images：公布真相时群发
  "faq": [
    { "keywords": ["钥匙"], "answer": "没有 DM 时，玩家提问命中关键词就自动用这句回答" }
  ],
  "host_notes": "主持手册：只给 DM 看（节奏建议、哪些问题不能直接答等）"
}
```

各字段的长度上限见 `packages/engine/src/games/jubensha/pack.ts` 里的 `packSchema`。录入完先校验：

```bash
bot-game-mcp check-script /私有目录/045.json
```

校验通过后可以离线模拟一局，看流程和文字是否顺：

```bash
bot-game-mcp simulate jubensha --players 6 --humans 1 --seed 1 --scripts /私有目录
```

**录入建议（给缪斯）**

- 图片线索：原图上传到云盘里这个剧本的文件夹，在 `images` 里登记文件名，并在需要发图的地方引用图片 id。每张图都要写 `caption`：真人玩家收到图片和说明，AI 玩家只能看到说明，所以说明要把图上的关键信息（文字、时间、位置关系）写全。
- 分幕按原剧本的「轮次 / 搜证」来切，每一幕的私密线索只给拿到它的角色。
- `faq` 写玩家最常问的客观事实，例如时间、地点、物品归属。答案不能透露凶手。
- `host_notes` 写给 DM：每幕的重点、常见卡点、哪些问题要含糊回答。

## 三、图片素材库

图片不进数据包，放在素材库里，二选一：

- **Google 云盘**（推荐，本体留在云盘，不占服务器空间）：
  1. 在 Google Cloud 建一个服务账号，开启 Drive API，下载它的 JSON 密钥，放到服务器的私有路径。
  2. 云盘里建一个根文件夹，只共享给这个服务账号（查看者）以及录入的人。根文件夹下每个剧本建一个子文件夹，用剧本 id 命名（如 `045`），图片放进去。
  3. 配置：`"drive": { "folderId": "<根文件夹 ID>", "credentialsFile": "<密钥路径>" }`。
  4. 开局时引擎把这一局要用的图下载到 `assetCacheDir/<对局ID>/`。对局结束 15 分钟后自动删除；如果中途有缺失，会按需重新下载。
- **本地目录**：`"assetsDir": "<目录>"`，图片放在 `<目录>/<剧本id>/<文件名>`。

检查图片是否都在：`bot-game-mcp check-script 045.json --config botgame.config.json`（云盘）或 `--assets <目录>`（本地）。

发送方式：

- 代码裁判（`bot-game-referee`）以 OneBot 图片消息发出图片，后面跟着文字说明。
- AI 裁判和 `text` 格式拿不到图片，只有「[图片]」加说明。
- 图片读取失败（云盘不可用、文件缺失）时同样只发说明，游戏不会卡住。

## 四、流程

1. **开局**：
   - 群里公布选角和每个角色的公开介绍；
   - 私发人物剧本；
   - 有 DM 时，私发 DM 简报；
   - 播报开场念白和开场图片。
2. **自我介绍**：按座位顺序每人一段（`intro_timeout_s`）。
3. **每一幕**：
   1. 播报公开内容，私发本幕的私密线索。
   2. **阅读**：每人发「读完」（`read_timeout_s`）。
   3. **自由讨论**：谁想说就说，限时 `discuss_minutes` 分钟，每人每幕最多 `discuss_max_msgs` 条。
      - AI 玩家不能连说两条，要等别人接话。
      - 发「过」表示本幕不再发言。
      - 所有人都「过」了、用完条数，或者时间到，就进入下一幕。
4. **投票**（`vote_timeout_s`）：不能投自己，可以弃票。得票最多且唯一的人是凶手就算破案。
5. **坦白**：凶手此时才收到认罪书，按它在群里坦白（`confess_timeout_s`）。超时则由程序代念认罪书。
6. **结局**：
   - 播报结局念白和真相；
   - 公布全部角色；
   - 破案时侦破方胜，否则凶手胜。

**提问**：玩家随时可以私下问 DM，每幕最多 `ask_limit` 次。

- 有 DM 时：问题转给 DM，群里只 @DM 提醒「有玩家私下提问」，不说是谁问的。
- 没有 DM 时：按 `faq` 关键词自动回答，没命中就提示「以你自己的剧本为准」。

## 五、开房选项

| 选项 | 默认 | 说明 |
|---|---|---|
| `script` | 空 | 剧本 id；库里只有一个剧本时可省略 |
| `host` | 空 | DM 的 QQ 号或昵称。DM 必须报名，不分配角色，此时报名人数应为 players+1。DM 没报名就由程序主持 |
| `cast` | `{}` | 指定选角：`{"QQ号": "角色key"}`，其余随机 |
| `intro_timeout_s` | 120 | 每人自我介绍时限 |
| `read_timeout_s` | 120 | 每幕阅读时限 |
| `discuss_minutes` | 8 | 每幕讨论时长（剧本里的 `discuss_minutes` 优先） |
| `discuss_max_msgs` | 6 | 每人每幕最多发言条数 |
| `vote_timeout_s` | 120 | 投票时限 |
| `confess_timeout_s` | 180 | 坦白时限 |
| `ask_limit` | 3 | 每人每幕最多提问次数 |

## 六、DM 怎么用

DM 是一个正常报名的座位，用开房选项 `host` 指定。小屋里让克蕾雅当 DM：`host=3127771953`。

DM 的 `get_view` 能看到：

- 真相、凶手、主持手册；
- 全部人物剧本和各幕内容；
- 待回答的提问（`open_questions`）。

DM 随时可用的动作：

| 动作 | MCP（`act`） | 真人 DM 指令 |
|---|---|---|
| 群里念白、串场 | `speech`，`text` | 直接在群里说 |
| 私下回答 | `answer`，`target`=提问者座位，`text` | 私聊裁判 `回复3 两把` |
| 提前结束当前环节（自我介绍、阅读、讨论） | `next` | `下一步` |
| 延长当前环节（阅读、讨论），每环节最多 2 次 | `extend`，`number`=1~5 分钟 | `延长3分钟` |

DM 的发言会进入发言记录，群里显示为「（DM）」。DM 不投票，也不参与胜负。
